# 안전하게 돌리기 — VM 과 Tor

크롤러가 여는 쪽은 다크웹 포럼과 랜섬 그룹의 유출 사이트입니다. 그 쪽을
여는 일에는 두 방향의 위험이 있습니다.

    나가는 쪽   저쪽 로그에 우리 주소가 남습니다. 한국 주소면 우리가
                누구인지 좁혀집니다
    들어오는 쪽 그 쪽 페이지가 우리 기기로 내려옵니다. 무엇이 섞여
                있을지 모릅니다

Tor 는 첫 번째만 막습니다. 두 번째는 VM 이 막습니다. 서로 대체가
안 됩니다. 둘 다 해야 합니다.

| 층 | 막는 것 | 안 막는 것 |
|---|---|---|
| Tor | 목적지가 우리 IP 를 보는 것 | 우리 기기가 오염되는 것 |
| VM | 우리 기기가 오염되는 것 | 목적지가 우리 IP 를 보는 것 |
| 간격·차례표 | 상대 서버를 힘들게 하는 것 | 자동 도구라는 것이 드러나는 것 |

---

## 무엇을 쓸까

이 PC 에는 셋이 다 있습니다.

| 고르는 것 | 격리 | 준비 | 언제 |
|---|---|---|---|
| VirtualBox VM | 강함 | 30분 | **평소. 이것을 씁니다** |
| WSL2 | 중간 | 5분 | 급할 때. 망을 호스트와 나눠 씁니다 |
| 윈도우 호스트 | 없음 | 0분 | 쓰지 않습니다 |

WSL2 는 파일시스템이 나뉘고 V3 의 `python.exe` 감시에서도 벗어납니다.
다만 망은 호스트를 지나고 `/mnt/c` 로 윈도우 파일이 그대로 보입니다.
**격리라기보다 칸막이입니다.** 급할 때만 씁니다.

## VirtualBox VM 에 올리기

### 1. VM 을 고릅니다

`kali-linux-2026.2` 가 이미 있습니다. 그것을 쓰거나, 깨끗한 Debian 을
새로 만듭니다. Kali 는 도구가 많이 깔려 있어 무엇이 밖으로 나가는지
알기 어렵습니다. 새로 만드는 쪽이 낫지만 있는 것을 써도 됩니다.

    VBoxManage list vms

### 2. 호스트와 이어진 길을 끊습니다

VM 설정에서 이 셋을 **끕니다.**

    공유 폴더        끕니다. 켜 두면 오염이 윈도우로 건너옵니다
    클립보드 공유    끕니다
    드래그 앤 드롭   끕니다

망은 NAT 로 둡니다. 브리지로 두면 VM 이 학교·집 망에 직접 붙어
MAC 주소가 그대로 나갑니다.

### 3. 한 줄로 자리를 만듭니다

저장소를 받은 뒤 이것만 돌리면 3~9 를 다 합니다.

```bash
bash scripts/돌릴자리-만들기.sh
```

tor 설치 · torrc 규칙 · 띄우기 · 실제로 나가 보기 · 파이썬 부품 ·
환경 변수 · 점검까지 합니다. 노션 토큰만 사람이 넣습니다.

아래는 그 스크립트가 무엇을 하는지입니다. 손으로 해도 됩니다.

### 3-1. VM 안에 Tor 를 깝니다

```bash
sudo apt update && sudo apt install -y tor
```

`/etc/tor/torrc` 를 열어 아래를 넣습니다.

```
# 표준 라이브러리가 SOCKS 를 못 타서 HTTP CONNECT 를 씁니다.
HTTPTunnelPort 9080

# 한국 출구를 안 씁니다. Tor 에도 한국 출구가 있어서, 안 막으면
# 우리 IP 는 아니어도 한국 주소가 남습니다.
ExcludeExitNodes {kr}
StrictNodes 1
```

`StrictNodes 1` 이 있어야 위 제외가 지켜집니다. 없으면 Tor 가 사정에
따라 어깁니다.

**대신 회로 만들기가 느려집니다.** 쓸 수 있는 출구가 줄기 때문입니다.
2026-08-28 WSL2 에서 처음 붙는 데 5분 걸렸습니다. 로그에 이런 줄이
나오면 정상입니다.

    All current guards excluded by path restriction type 2;
    using an additional guard.

한 번 붙은 뒤로는 3~5초면 한 곳을 봅니다.

```bash
sudo systemctl enable --now tor
sudo systemctl status tor        # active 인지 봅니다
```

### 4. 저장소를 받고 부품을 깝니다

```bash
git clone https://github.com/MukSilver/darkchoco.git
cd darkchoco
python3 -m venv .venv && source .venv/bin/activate
pip install -e packages
```

### 5. 환경 변수를 넣습니다

`~/.bashrc` 끝에 붙입니다.

```bash
export TOR_SOCKS_PROXY=http://127.0.0.1:9080
export NOTION_TOKEN=...          # 노션 통합 토큰
export PYTHONIOENCODING=utf-8
```

**노션 토큰을 저장소에 넣지 않습니다.** VM 안에만 둡니다.

### 6. 확인합니다

```bash
python dc.py doctor --net
```

이렇게 나와야 합니다.

    ── 밖으로 나가는 길 ──
    프록시   http://127.0.0.1:9080
    OK Tor 를 타고 있습니다. 밖에 남는 주소는 <출구 IP> 입니다.

`!!` 가 뜨면 그대로 두고 크롤러를 돌리지 않습니다. 크롤러도 스스로
막지만, 여기서 먼저 봐야 무엇이 문제인지 압니다.

출구 IP 가 정말 한국이 아닌지 눈으로 보려면 그 IP 를 whois 로 봅니다.
확인하려고 IP 조회 사이트에 붙는 것도 요청 하나이니, 필요할 때만
합니다.

### 7. 차례표에 겁니다

윈도우 작업 스케줄러가 아니라 VM 안의 cron 을 씁니다.

```bash
crontab -e
```

```
*/30 * * * * cd ~/darkchoco && ./.venv/bin/python dc.py auto >> ~/darkchoco-auto.log 2>&1
```

30분마다 부르지만 실제로 도는 것은 주기가 찬 것뿐입니다. 무엇이 언제
도는지는 차례표(`hub/places/run.py` 의 `주기`)가 정합니다.

    telegram  360분
    forum     720분
    ransom    720분

## WSL2 로 급할 때

```powershell
wsl -d Ubuntu-24.04
```

안에서는 위 3~7 과 같습니다. cron 대신 WSL 을 띄워 두거나 윈도우
작업 스케줄러가 `wsl -d Ubuntu-24.04 -- ...` 를 부르게 합니다.

**호스트로 새는 길을 압니다.**

  · `/mnt/c` 로 윈도우 파일이 그대로 보입니다
  · 망이 호스트를 지납니다. V3 가 볼 수 있습니다
  · WSL 안에서 윈도우 실행 파일을 부를 수 있습니다

이것을 알고 쓰는 것과 모르고 쓰는 것이 다릅니다.

**배포판끼리 localhost 를 함께 씁니다.** Ubuntu-24.04 에서 tor 를
띄워 두고 Ubuntu-22.04 에서 또 띄우면 9050 에서 부딪혀 설정이 통째로
실패합니다. 한 자리에서만 띄우고 나머지는 그것을 쓰거나, `SocksPort`
까지 옮기십시오.

    /etc/tor/torrc 에  SocksPort 9151

`sudo` 도 배포판마다 다릅니다. Ubuntu-24.04 는 root 로 도는데 22.04 는
아닙니다. 비밀번호를 묻는 자리면 먼저 넣어 두고 돌리십시오.

    sudo -v && bash scripts/돌릴자리-만들기.sh

## V3 가 막을 때

V3 가 `python.exe` 의 다크웹 도메인 접근을 막습니다. 실제로 이런 것들이
막혔습니다 — `prologic.su` · `leaky.pro` · `crdclub.su` ·
`cardmafia.net` · `blackbones.cc`.

**「신뢰 사이트로 추가」를 누르지 마십시오.** 그것은 그 다크웹 사이트를
V3 신뢰 목록에 넣는 일입니다. 나중에 브라우저로 실수로 들어가도 안
막힙니다. 우리가 원하는 것은 조사 도구의 예외이지 그 사이트의 신뢰가
아닙니다.

VM 으로 옮기면 이 문제가 없어집니다. V3 는 윈도우 것입니다.

호스트에서 돌려야 한다면 V3 예외를 **저장소 폴더에** 겁니다. 도메인이
아니라 폴더입니다.

## 크롤러가 스스로 지키는 것

문서를 안 읽어도 이것들은 지켜집니다. 사람이 빠뜨리는 것을 코드가
막습니다.

  · `TOR_SOCKS_PROXY` 가 없으면 **밖으로 안 나갑니다.** 빈손으로
    돌아오지, 맨 연결로 채워 오지 않습니다
  · 나가는 길이 `hub/places/egress.py` 한 곳뿐입니다.
    `test_맨IP금지.py` 가 다른 길이 생기는지 봅니다
  · 연결이 안 된 것을 `offline` 으로 안 적습니다. 백신·Tor·망 문제를
    「사이트가 죽었다」로 노션에 적으면 사람이 조사한 값이 날아갑니다
  · 두드리지 못한 줄은 노션에 아무것도 안 씁니다. 확인일도 안 씁니다

일부러 끄려면 이렇게 합니다. **끌 때는 무엇을 끄는지 알고 끄는
것입니다.**

```bash
export DARKCHOCO_TOR_SKIP=telegram      # 이 갈래만 맨 연결
export DARKCHOCO_ALLOW_DIRECT=1         # 전부 맨 연결
```

## 아직 안 막은 것

  · **요청 지문.** `urllib` 이라 크롬 User-Agent 를 적어도 TLS
    핸드셰이크와 헤더 순서가 실제 크롬과 다릅니다. IP 는 가려져도
    자동 도구라는 것은 드러납니다
  · **행동 패턴.** 같은 순서로 같은 목록을 주기적으로 훑으면 출구 IP 가
    바뀌어도 그 자체가 서명입니다
  · **Tor 출구 차단.** 포럼과 클라우드플레어가 Tor 출구 목록을 압니다.
    켜면 못 보는 곳이 늘어날 수 있습니다. 다만 2026-08-28 실측에서는
    BreachForums · LeakForums · t.me 셋 다 Tor 로 그냥 보였습니다.
    막히면 `못본이유` 에 남으므로 얼마나 막히는지 세어 보고 다시 정합니다
