## 2. 이 산출물의 차별점 — 왜 존재하나

1. **확인된 항목에만 조치를 냅니다.** 일반 보안 수칙 나열은 실제 피해와 무관한
   조치까지 시킵니다. 「안 해도 된다」를 쓰려면 샘플을 연 근거가 있어야 하는데,
   기관 안내문은 그 근거가 없어 그 줄을 못 씁니다.
2. **항목별 창구 연결표가 국내에 없습니다.** 각 기관이 자기 서비스만 안내합니다.
   「무엇이 털렸으니 어디로 가라」로 묶은 화면이 이 산출물입니다.
3. **결합 위험을 설명합니다.** 이름+전화 → 사칭 피싱처럼, 단독으로 안전해 보이는
   항목이 합쳐질 때 생기는 위험을 확인된 항목끼리만 계산해 보여줍니다.

## 3. 데이터를 왜 셋으로 갈랐나

- `leak-map.json` — 조사 결과. 노션에서 구움
- `guide.json` — 조치·창구·결합. **조사 결과가 아니라 팀이 재서 채우는 값**
- `vocab.json` — 둘이 같이 쓰는 어휘. 전부 노션 실제 select 값, 지어낸 이름 없음

가른 덕에 조치 19개는 조사 진척과 무관하게 지금 채워질 수 있고,
화면마다 다른 이름이 나오는 사고가 원천적으로 막힙니다.

## 4. UX 판정

사고 대응 안내 UX 선례(HIBP · Firefox Monitor · FTC)를 조사한 판정입니다.

**채택**
- 시급성은 2~3단. 색과 텍스트를 병기(색만으로 가르지 않음)
- 확인 안 된 항목은 회색 행으로 「지금 할 일이 없음」 명시 — 경고 습관화·보안 피로 근거
- 체크 상태 `localStorage`(이 브라우저에만). 완료율 19%→34% 근거.
  **식별 정보는 절대 저장 안 함**
- 창구는 「기관명+번호+준비물 한 줄」을 본문에 인라인 (별도 링크 섹션 금지)
- 인쇄에서 외부 링크만 URL을 활자로. 체크박스는 펜용 빈 사각형

**기각**
- 시급성 3단 이상·위험 점수화 — NIST 보안 피로(결정 수 최소화) 위반
- 0%에서 시작하는 긴 진행률 바 — 빈 바 역효과
- confetti 완료 연출 — 사고 대응 톤 불일치
- QR 외부 API 생성 — 오프라인·CDN 금지 제약에서 빈 이미지
- 첫 방문 안내 오버레이 — 아무도 안 봄. 링크 글자 자체를 설명으로
