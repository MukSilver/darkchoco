# 개인정보 유출 생태계 지도 — 시스템 명세서 (DC-MAP-SYS-001)

> 판 1.0 (2026-08-28). 화면명세.md의 지도 부분(M1~M5)을 시스템 명세로 승격하고,
> 실제 규모(자리 887 · 사고 300) 프로토타입에서 확인된 사실을 반영했습니다.

## 1. 한 문장

**유출물은 위(오픈웹)에서 나거나 훔쳐져 아래(다크웹)로 내려가 팔리고, 다시 위로 올라와 남는다** —
이 한 문장을 두 층의 벌집 영토판 하나로 보여줍니다.

## 2. 세계 모형

| 개념 | 정의 | 값의 출처 |
|---|---|---|
| 층(layer) | 그 자리에 닿는 데 필요한 것. `sky`(검색하면 나옴) / `deep`(주소나 계정이 필요) | 포럼 DB 어니언 주소·가입 필요, 랜섬웨어 DB 주소 |
| 업종(kind) | 자리의 장사 방식. forum / ransom / telegram / archive / market / broker | 어느 DB에서 왔는가 + 형식 select |
| 대륙 | 층 × 업종 중 실제로 존재하는 조합. 씨앗에서 BFS로 성장 | 계산값 (vocab.json) |
| 자리(place) | 포럼 하나, 그룹 하나, 채널 하나 = 벌집 칸 덩어리 하나 | 포럼·랜섬웨어·텔레그램 DB 한 줄 |
| 길(flow) | 자리 사이의 유출물 이동. 같은층 / 내려감(drop) / 올라옴(rise) / 노출(exposure) / 후계(succession) | 「연결된 곳」 접두어 + 사고 이동 집계 |
| 사고(case) | 수집 DB 한 줄. 지나간 자리 목록(hops)과 항목별 확인 상태(items)를 가짐 | 수집 DB + 검증 DB |

**면적 = 그 자리에서 확인한 사고 수.** 평행 기울임 투영이라 앞뒤 면적 비가 보존됩니다(원근 아님).
**붙어 있음에 뜻 없음.** 대륙 안 자리끼리의 인접은 배치 알고리즘의 결과일 뿐, 관계는 선으로만 표현합니다.

## 3. 데이터 계약 (leak-map.json)

빌드 단계(`tools/build_data.py`)가 노션을 읽어 굽고, 화면은 이 파일만 읽습니다.
노션 토큰은 브라우저에 절대 나가지 않습니다.

```
meta      basis_date · edition · counts{forum, ransom, collected}
layers[]  id(sky|deep) · name · sub
kinds[]   id · name · color
places[]  id · name?(조사한 곳만) · layer · kind · status(online|offline|미확인|seized|인계됨)
          · investigated · cases · korea? · first_seen? · last_seen? · note?
flows[]   from · to · kind(flat|drop|rise|exposure|succession) · label
          · confidence(confirmed|probable) · cases(사고에서 집계 — 지어내지 않음)
cases[]   id · title(업종+자료형, 실명 없음) · industry · posted · verdict · gate
          · items{항목id: claimed|confirmed} · hops[{place,name,layer,kind,relation,at?}]
          · reach{state,layer,kind,places_n} · evidence_kind
stats     reported ≥ matched ≥ circulating ≥ judged (깔때기)
```

**reach는 사람이 적지 않습니다.** 마지막으로 확인한 자리의 층과 업종이 정합니다.
`deep-only`(다크웹 안) / `surfaced`(오픈웹까지) / `public`(검색까지) / `unknown` 넷뿐입니다.

## 5. 반출 규칙 (SR)

- SR-1 **도메인·주소·들어가는 법은 싣지 않습니다.** 이름까지만. 검사에서 도메인 꼴이 걸리면 그리지 않고 멈춥니다.
- SR-2 **조사하지 않은 자리는 이름조차 내보내지 않습니다.** 「일부러 반출하지 않음」·「웹에 올림」 필터를 거치기 전이기 때문입니다. 칸 수만 내보냅니다.
- SR-3 사고 제목에 대상 조직 실명을 쓰지 않습니다. 업종 + 자료 형태로 적습니다.
- SR-4 게시자 핸들·지갑 주소·연락 수단은 지도 데이터에 아예 넣지 않습니다.
- SR-5 노션 토큰·API 키는 빌드 단계까지만 존재합니다. 산출 JSON에 어떤 자격증명도 남지 않습니다.

## 7. 실측 (2026-08-28, 자리 887 기준)

- SVG 폴리곤 2,016 · 전체 노드 3,312 · getBBox 24.7ms
- `leak-map.json` 368,116 B → **gzip 15,354 B (4%)**. 무명 자리 869개가 거의 같은
  모양이라 압축률이 96%입니다. 분할 기준(gzip 100KB)에 한참 못 미쳐 **쪼개지 않습니다**
- 압축 덤프(`separators=(',',':')`)로 다시 구우면 256,132 B · gzip 13,705 B
- 계약 검사 위반 0
- 병목은 파싱(1ms 미만)이 아니라 **887자리 배치 이중 루프**입니다. 루프 전에
  `requestAnimationFrame`을 한 번 넣어 스켈레톤이 실제로 그려지게 합니다

## 8. 렌더링 스택 결정

**순수 SVG, 라이브러리 0개.** 원소 약 1,500개는 SVG 임계(3,000~5,000)의 절반이고,
인쇄 정지판·키보드·빔 선명도·무빌드가 전부 SVG 편입니다. 성능은 교체가 아니라
규율로 지킵니다 — filter 전면 금지, 이벤트 루트 위임, 상태는 클래스 토글, 색은 CSS 변수.

사이트 전체 구조(URL·상태·로딩·배포·보안)는 **`사이트-구조.md`(DC-SITE-001)** 에
따릅니다. 여기서는 지도 고유의 것만 적습니다.

## 8-1. 접근성 (SC 4.1.2 · 1.1.1 · 2.5.8)

**현재 위반**: 887개 `g`에 `tabindex="0" role="button"`이 붙어 있는데 부모 SVG가
`role="img"`라 자식이 전부 presentational로 무시됩니다. 포커스는 가는데 접근성
트리에 이름도 역할도 없습니다 — ACT 307n5z 위반. 미조사 869곳은 `name`이 없어
`aria-label`이 「undefined · 확인한 사고 1건」으로 나갑니다.

- SVG 안 `tabindex` **0개**. `role="img"` 유지 + `<title>`·`<desc>` 연결
- 클릭·포커스는 `investigated:true`인 **18곳**만, SVG 위 HTML `button` 프록시가 받음
- `role="group"` + roving tabindex (화살표는 기하 최근접, Home/End, Esc 복귀)
- 좌표는 `getBoundingClientRect` 차이. **viewBox 재계산 직후에도 반드시 한 번** 동기화
- 텍스트 대안은 **필수**. 887행 표가 아니라 `<details>` 안 표 두 개
  (층·업종별 집계 / 조사한 18곳). 미조사 이름은 표에도 안 올라갑니다
- 밀도·판정을 색만으로 구분하지 않음 — 테두리 두께 또는 해칭 `<pattern>` 병행

## 8-2. URL 상태

`case`(사고) · `place`(자리) · `k`(업종 칩) · `q`(검색어 40자) · `view`(stage).
선택은 `pushState`, 타이핑·토글은 250ms 디바운스 `replaceState`.
줌·팬은 싣지 않습니다 — 휠 한 번에 수십 번 호출되어 사파리 제한에 걸리고,
빔과 노트북의 화면 비율이 달라 좌표를 복원해도 다른 그림이 나옵니다.
