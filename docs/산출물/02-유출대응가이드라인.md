# 유출 대응 가이드라인

작성일 2026-08-27 · 담당 김무근

---

## 1. 이름을 바꿉니다

**「개인 대응 가이드라인」 → 「유출 대응 가이드라인」**

원래 이름은 개인만 다루는 것처럼 읽히는데, 실제 내용은 대응 주체가 셋입니다.
같은 사건이라도 개인과 조직이 할 일이 다르기 때문에 셋을 다 다뤄야 쓸모가
있습니다. 이름이 내용보다 좁으면 「개인 가이드인데 왜 기업 대응이 있나」라는
질문을 받게 됩니다.

노션·발표 자료·보고서에서 쓰는 이름을 전부 새 이름으로 맞춥니다.

---

## 2. 대응 주체 셋

| 주체 | 대상 | 안내 내용 |
|---|---|---|
| 개인 | 자기 정보가 포함됐거나 확인하려는 사람 | 계정 보호, 피싱·명의도용 예방, 피해 확인·상담 |
| 피해 기업·기관 | 유출이 발생했거나 개인정보를 처리한 조직 | 사고 차단, 증거 보존, 영향 범위 확인, 통지·신고 판단 |
| 협력사·관계기관 | 공유 계정·문서·시스템·위탁정보로 연결된 조직 | 접근 차단, 자격증명 교체, 영향 확인, 공동 대응 |

자기 역할을 모르는 사용자는 간단한 질문 몇 개로 맞는 가이드로 보냅니다.

---

## 3. 이용 흐름

1. 기업·기관 또는 유출 사건을 찾습니다
2. 사건의 **검증 상태**와 확인된 유출 항목을 봅니다
3. **본인에게 해당하는 정보를 고릅니다**
4. 대응 주체를 고릅니다
5. 유출 항목과 역할에 맞는 조치를 시급성 순으로 받습니다

---

## 4. 이 산출물의 차별점

**확인된 항목에만 조치를 답니다.** 그리고 확인 안 된 항목에는 **「이 사건 기준
조치 없음」**이라고 적습니다.

일반 보안 수칙을 전부 나열하는 방식은 실제 피해와 무관한 조치까지 시키고, 안
해도 되는 일에 사람을 쓰게 만듭니다. 「안 해도 된다」를 쓰려면 샘플을 실제로 열어
확인한 근거가 있어야 합니다. **기관 안내문이 그 줄을 못 쓰는 이유가 근거가 없어서
입니다.**

각 조치 옆에는 그 조치를 권하는 근거가 된 유출 항목을 표시합니다.

**정보 결합 위험**도 같이 설명합니다. 단일 항목보다 조합이 위험합니다.

- 이름 + 전화번호 → 기관·기업 사칭 피싱
- 배송지 + 주문 내역 → 생활 패턴을 이용한 표적 사기
- 이메일 + 계정 식별자 → 다른 서비스 계정 추적과 대입 시도

## 5. 화면

| 화면 | 내용 |
|---|---|
| 1. 사건 찾기 | 서비스·회사 / 도메인 / 이메일·계정 세 갈래 검색. 검증 상태 배지 |
| 2. 유출 항목과 결합 위험 | 확인된 항목, 영향 대상, 규모, 위험 태그, 근거 요약 |
| 3. 대응 주체 선택 | 카드 셋. 역할을 모르면 질문으로 안내 |
| 4. 개인 가이드 | 시급성 3단 + 항목별 근거 표시 |
| 5. 피해 기업·기관 가이드 | 사고 인지 이후 시간순 업무 |
| 6. 협력사·관계기관 가이드 | 접근 차단·자격증명 교체·공동 대응 |

**핵심 화면은 2번입니다.** 사용자가 「내가 실제로 사용한 정보」를 직접 고르면
계정 탈취·피싱 사칭·금융 피해 세 위험도가 그에 맞춰 바뀝니다. 이 화면이 이
산출물이 왜 필요한지를 설명 없이 보여줍니다.

## 6. 시급성

**개인**

| 언제 | 무엇 |
|---|---|
| 지금 바로 | 공식 공지 확인, 의심 문자·전화·배송 링크 주의 |
| 오늘 안에 | 재사용 계정 비밀번호 변경, 2단계 인증, 로그인·결제 기록 확인 |
| 이후 30일 | 피싱·계정 활동 확인, 피해 증거 보관, 신고·상담 |

**피해 기업·기관**

| 언제 | 무엇 |
|---|---|
| 0~4시간 | 대응팀 소집, 추가 유출 차단, 시스템 격리, 로그·증거 보존 |
| 4~24시간 | 유출 항목·대상·규모·경위 및 협력사 영향 확인 |
| 24~72시간 | 법령상 통지·신고 요건 검토, 통지문·신고 자료 준비 |
| 이후 | 피해 지원, 원인 제거, 접근권한 개선, 재발 방지 |

**72시간을 모든 사고의 일괄 마감으로 표시하지 않습니다.** 해당 사고가 법령상
요건에 해당하는지 확인하는 판단 단계로 둡니다.

## 7. 한국 창구 연결

이 부분이 해외 안내문을 그대로 옮길 수 없는 지점입니다. 미국에서 신용 동결
한 번으로 끝나는 일이 한국에서는 창구가 갈립니다.

| 무엇 | 어디 |
|---|---|
| 계좌·대출·카드 개설 차단 | 금융감독원 개인정보 노출자 사고예방 |
| 휴대폰 명의도용 차단 | 명의도용 방지 서비스 |
| 본인확인 내역 조회 · 회원탈퇴 대행 | 개인정보 포털 |
| 침해 신고 | 개인정보침해 신고센터 118 |
| 분쟁조정 | 개인정보분쟁조정위원회 1833-6972 |

**항목별로 이 창구들을 연결해 주는 표가 지금 국내에 없습니다.** 각 기관이 자기
서비스만 안내하고, 「무엇이 털렸으니 어디로 가라」로 묶은 화면이 없습니다.

---

## 8. 생태계 지도와의 연동

지도에서 사건을 고르면 그 사건에서 확인된 유출 항목과 검증 상태가 가이드라인으로
넘어옵니다. 검증 상태에 따라 안내 수위를 바꿉니다.

| 검증 상태 | 안내 |
|---|---|
| 검증 완료 | 확인된 항목 기준 대응 안내 |
| 검토 중 | 사실관계 확인과 예방 중심 |
| 주장만 확인 | 유출을 단정하지 않고 주의사항만 |
| 허위 · 무관 판정 | **구체적 대응 생성 중단** |

마지막 줄은 **허문선 님이 먼저 적은 것입니다.** 초안에 「허위 판정 사건은 개인 조치를
산출하지 않도록 처리」라고 되어 있습니다. 이 산출물의 차별점을 만드는 줄이 여기서
나왔습니다.

같은 문서에 **조치별 체크박스와 완료 0/6 진행률, 완료 상태를 사건별로 따로 저장**하는
안도 있습니다. 이건 아직 화면에 안 들어갔습니다. 넣을지 정해야 합니다.

## 10. 배포 전 처리할 것

**「이 사건 기준 조치 없음」의 범위를 명확히 적습니다.** 샘플에서 확인되지
않았다는 뜻이지 전체에 없다는 뜻이 아닙니다. 배포본에는
**「샘플에서 확인되지 않았습니다 · 전체 확인은 아닙니다」**로 씁니다.

조치 문구는 배포 전에 개인정보보호위원회·KISA 안내와 대조합니다.
