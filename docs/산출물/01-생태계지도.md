# 개인정보 유출 생태계 지도

작성일 2026-08-27 · 담당 김무근

---

## 1. 무엇을 만드는가

개인정보 유출물은 한 곳에 머물지 않고 랜섬웨어 유출 사이트·해킹 포럼·텔레그램을
거치며 팔리고 재유통됩니다. 플랫폼별 조사 결과가 갈라져 있으면 특정 사건이 어떤
경로로 이동했는지 알 수 없습니다.

각 조사 영역의 데이터를 하나로 모아, **이동 경로와 플랫폼 간 연결을 한 화면에서
보는 지도**를 만듭니다.

---

## 2. 표현 방식 — 육각 영토판으로 확정

검토 과정에서 두 컨셉이 나왔고 **육각 영토판으로 정했습니다.**

| | 노드 그래프판 | **육각 영토판 (확정)** |
|---|---|---|
| 크기가 뜻하는 것 | 없음 | 활동 규모 |
| 위치가 뜻하는 것 | 연결 관계 | 카테고리 소속 |
| 주인공 | 선 | 면적 |
| 참고 | Recorded Future · Maltego | Weighted Voronoi · 육각 분할 |

**고른 이유는 위치와 면적에 뜻이 있어야 「지도」라는 이름값을 하기 때문입니다.**
노드 그래프는 엄밀히 네트워크 그래프이고, 노드를 아무 데나 옮겨도 뜻이 바뀌지
않습니다. 육각 영토판은 옮기면 소속이 바뀌고 크기를 바꾸면 규모가 바뀝니다.

카테고리는 서로 맞닿은 영역으로 두고, 카테고리 안에서 개별 엔티티를 다시 나눕니다.

- 포럼 · 커뮤니티
- 랜섬웨어 그룹
- 거래 시장
- 통신 인프라
- 유출 · 공개 사이트
- 접근 브로커 · 도구

## 3. 아직 안 정한 것 — 면적 기준

**이것이 지도의 핵심이자 지금 가장 큰 구멍입니다.**

원래 설계는 면적을 Activity Score로 잡았습니다. 포럼이면 최근 게시글 수·활성
사용자·신규 스레드, 랜섬웨어면 최근 30일 DLS 게시 수·게시 빈도로 0~100을
계산하는 방식입니다.

**문제는 그 값을 채울 데이터가 아직 없다는 것입니다.** 포럼 267곳을 확보했지만
직접 조사한 곳은 37곳이고, 그것도 게시판 구조와 활성도 기초 조사 수준입니다.
활동 지표를 지속 수집하는 파이프라인이 없습니다.

대안이 하나 있습니다.

| 안 | 면적 = | 지금 만들 수 있나 |
|---|---|---|
| A. Activity Score | 최근 활동 지표를 정규화한 0~100 | 아니오. 수집부터 필요 |
| **B. 확인 수준** | **우리가 확인한 건수·깊이** | **예. 지금 데이터로 바로** |

B로 가면 직접 조사 37곳은 넓게, 목록만 확보한 230곳은 좁게 그려집니다. 지도 모양은
그대로 두고 산식만 바뀝니다. **「이 숫자 어디서 나왔나요」에 「우리가 센 겁니다」로
답할 수 있다는 것**이 B의 값입니다.

발표 전에 정합니다. 정하기 전까지 화면에 나오는 점수는 예시이며, 화면 하단에
그 사실을 표기합니다.

## 4. 화면 다섯

| 화면 | 목적 |
|---|---|
| 메인 — Ecosystem Map | 전체 구조를 한눈에. 카테고리 영토 + 관계선 + 선택 요약 |
| 카테고리 상세 | 한 카테고리 안의 엔티티 순위·상태·최근 변화 비교 |
| 엔티티 상세 | 개별 포럼·그룹의 기본 정보, 추이, 관계, 이벤트, 출처 |
| 관계 네트워크 | 선택 엔티티 중심으로 검증된 관계만 표시 |
| 타임라인 | 시간 슬라이더로 과거 시점의 상태 재현 |

메인 화면에서 모든 관계를 항상 띄우면 못 읽습니다. 기본은 중요 관계만, 엔티티를
누르면 그 엔티티 관련 관계만 켭니다. **실선은 확인된 관계, 점선은 추정입니다.**

## 5. 데이터 모델

```
Entity           id · name · type · status · first_seen · last_seen · score · language
ActivityHistory  entity_id · observed_at · score · metrics_json
Relationship     source · target · type · first_seen · last_seen · confidence · status
Source           entity_id · relationship_id · source_name · source_url · published_at
Event            entity_id · event_type · event_date · description · source_id
```

관계 유형은 근거가 확인된 상호작용만 씁니다. Recruitment · Communication ·
Data Leak · Data Sale · Access Sale · Partnership · Operator Migration ·
User Migration · Successor · Conflict.

---

## 6. MVP 범위

- 카테고리 6개 내외 · 엔티티 30~50개
- 영역 자동 분할과 면적 조절
- 엔티티 hover · click · 상세 화면
- 카테고리 간 관계선 + 근거·출처
- 기본 타임라인
- **관리자 수동 입력** — 자동 수집은 이번 학기에 붙이지 않습니다

자동 OSINT 수집은 난이도가 가장 높고, 지도 렌더링과 분리된 별도 파이프라인으로
설계합니다.
