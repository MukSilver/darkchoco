# 다크초코 팀 GitHub 운영안

작성일 2026-08-26 · 고침 2026-08-30 · 다크초코 (화이트햇 스쿨 4기)

지금 여섯 개 저장소가 팀원 개인 계정에 흩어져 있습니다. 이것을 조직 하나로
모으고, 겹치는 부품을 공용으로 뽑아, 각자 자기 도구를 계속 고도화하면서도
공통 부분은 한 번만 고치는 구조를 만드는 것이 이 문서의 목적입니다.

---

## 1. 지금 상태

여섯 저장소를 전부 확인했습니다(8/26). 텔레그램 두 개는 같은 코드에서 갈라져
나와 지금도 각자 자라고 있습니다. 아래 표는 그때 상태입니다.

| 저장소 | 담당 | 무엇을 하나 | 상태 |
|---|---|---|---|
| whs4-dark | 성민서 | 포럼 크롤링 (Docker + Tor + Playwright) | 수집기 7개 구현 (8/28 기준) |
| Notion-DLS | 안유빈 | 다크웹 유출 사이트 관측 → 노션 | 완성 |
| Kr-Leak-alarm | 안유빈 | 랜섬웨어 DLS 한국 피해 알림 + 대시보드 | 완성 |
| telegram-channel-monitor | 이수빈 | 텔레그램 채널 수집 → 노션 반영 | 완성 |
| darknetzzzz_telegram | 성민서 | 텔레그램 한국 관련 게시물 → Discord 알림 | 완성 |
| darkchoco-skills | 최현서 | 유출 주장 검증 스킬 + 도구 | 완성 |

확인 과정에서 겹치는 부분이 세 갈래로 드러났습니다.

- **텔레그램 접속·수집 코드가 두 저장소에 복사되어 있습니다.** `collect_messages.py`가
  이미 312줄 갈라졌고, `check_login.py`·`list_channels.py`는 3줄 차이입니다. 놔두면
  더 벌어집니다.
- **`ransomware.live` API를 Notion-DLS와 Kr-Leak-alarm이 각자 긁고 있습니다.** 같은
  데이터를 하루 두 번씩 두 번 받습니다.
- **노션 API 래퍼가 세 벌 있습니다.** Notion-DLS, telegram-channel-monitor,
  darkchoco-skills가 같은 일을 따로 하고, 토큰 읽는 방식도 다릅니다.

## 2. 저장소 구조

저장소를 여러 개로 쪼개지 않고, 하나 안에서 폴더로 나눕니다. 이유는 하나입니다.
크롤러·수집·검증이 전부 같은 노션 DB에 같은 양식으로 쓰기 때문에, DB 스키마가
바뀌면 모두 같이 바뀌어야 합니다. 저장소가 갈라져 있으면 그때마다 손이 여러 번
갑니다.

```
darkchoco/                       (조직 · 저장소 하나)
  dc.py                          입구. 목록 · 사용법 · 상태 · 차례표
  hub/                           지휘 — 언제 돌릴지 · 노션에 쓰기
    places/                      「어디가 있고 살아있나」 → 다크웹 DB 3개
    events/                      「무슨 글이 올라왔나」  → 수집·검증 DB
    sched.py                     주기
  packages/                      공용 부품 — 여기만 공유합니다
    dc_telegram/                 텔레그램 로그인·채널 목록·메시지 수집
    dc_notion/                   노션 API 래퍼
    dc_ransomfeed/               ransomware.live · ransomlook · ransomfeed
    dc_safety/                   안전 HTTP · 차단 호스트
    dc_store/                    출처가 달라도 칸이 같은 한 표
    dc_console/                  윈도우 한글 콘솔
  apps/                          각자 소유 — 계속 따로 고도화합니다
    forum-crawler/               성민서   (whs4-dark)
    dls-observatory/             안유빈   (Notion-DLS)
    kr-leak-alarm/               안유빈   (Kr-Leak-alarm)
    tg-notion-report/            이수빈   (telegram-channel-monitor)
    tg-korea-alert/              성민서   (darknetzzzz_telegram)
  skills/                        최현서   (darkchoco-verify-ko)
  scripts/                       VM 자리 만들기 · 올리기 · 돌리기
  docs/                          검증 기준 · 양식 · 계획서
  .github/                       CODEOWNERS · PR 템플릿 · 워크플로
```

`hub/` 는 8/26 이 문서를 쓴 뒤에 생겼습니다. **부품도 앱도 아닌 세 번째
층입니다.** 앱을 부르고, 노션에 쓰고, 차례를 셉니다.

    packages/  ←  hub/  ←  dc.py
                   ↓
                 apps/  ·  skills/     (hub/events/sources/ 만 부릅니다)

방향이 한쪽입니다. `apps/` 는 `hub/` 를 모릅니다. `packages/` 는 둘 다
모릅니다.

앱 다섯 개는 각자 폴더 안에서 자기 것만 만집니다. 공유하는 것은 `packages/` 뿐입니다.

## 3. 무엇을 통합하고 무엇을 두는가

### 통합하는 것 — 공용 패키지 네 개

| 패키지 | 합칠 대상 | 어떻게 |
|---|---|---|
| `dc-telegram` | 두 텔레그램 앱의 로그인·수집 | 최신 판을 정해 그것을 부품으로 승격 |
| `dc-notion` | 노션 래퍼 세 벌 | 한 벌로 합치고 토큰 규약 통일 |
| `dc-ransomfeed` | ransomware.live·ransomlook·ransomfeed | Kr-Leak의 `Source` 추상 클래스를 승격 |
| `dc-safety` | 안전 HTTP·차단 호스트 | Kr-Leak의 `SafeHttpClient`를 표준으로 |

Kr-Leak-alarm이 이미 소스 어댑터를 `Source` 추상 클래스로 잘 짜 두었고, Notion-DLS가
VM과 호스트를 잘 나눠 두었습니다. 새로 짜는 것이 아니라 잘 만들어진 쪽을 부품으로
끌어올리는 작업입니다.

### 통합하지 않는 것

| 두는 것 | 이유 |
|---|---|
| ~~크롤러 실행부 세 개~~ | **8/28 에 뒤집혔습니다.** `hub/places/` 로 합쳤습니다. 분기 덩어리가 안 된 이유는 갈래마다 조사기를 따로 두고 `run.py` 는 부르기만 하기 때문입니다 |
| 앱 다섯 개 | 목적이 서로 다릅니다. 노션 반영과 Discord 알림은 다른 일입니다 |
| 대시보드 | 실제 대시보드는 Kr-Leak 하나뿐입니다. 통합할 짝이 없습니다 |

포럼 크롤러(whs4-dark)는 노션도 ransomware.live도 안 쓰고 HTTP도 Playwright라,
공용 부품과 겹치는 것이 거의 없습니다. 성민서 님은 공용 작업을 기다리지 말고 지금
그대로 이어가면 됩니다.

## 4. 각자 계속 따로 고도화가 되는가

됩니다. 이것이 이 구조를 택하는 가장 큰 이유입니다. 부품과 앱을 나누면 두 가지가
동시에 성립합니다.

- **이수빈 님이 `tg-notion-report`를 고쳐도 성민서 님의 `tg-korea-alert`는 흔들리지
  않습니다.** 서로 다른 폴더이기 때문입니다.
- **그런데 텔레그램 로그인 방식이 바뀌면 `dc-telegram` 한 곳만 고치면 두 앱에 함께
  반영됩니다.** 지금은 두 파일을 따로 고쳐야 하고, 그중 하나는 빠지기 쉽습니다.

지켜야 할 규칙은 하나입니다. **`packages/`는 `apps/`를 절대 import 하지 않습니다.**
부품이 앱을 모르면, 앱이 아무리 바뀌어도 부품은 안전하고, 부품을 고쳐도 각 앱은
자기 속도로 따라오면 됩니다. 이 방향만 지키면 서로 얽히지 않습니다.

## 5. 운영 규칙

### 소유와 리뷰

`.github/CODEOWNERS`에 폴더마다 주인을 지정합니다.

```
/apps/forum-crawler/     @minsmiths
/apps/dls-observatory/   @60secAgo
/apps/kr-leak-alarm/     @60secAgo
/apps/tg-notion-report/  @leesubhin060-max
/apps/tg-korea-alert/    @minsmiths
/skills/                 @grute02
/packages/               @MukSilver @minsmiths @60secAgo @leesubhin060-max
/hub/                    @MukSilver
/hub/places/write.py     @MukSilver @60secAgo
/hub/places/egress.py    @MukSilver @60secAgo
```

- 자기 앱 폴더는 본인이 바로 머지해도 됩니다. 빠르게 가야 하는 부분입니다.
- **`packages/` 와 `hub/` 를 건드리는 PR은 리뷰 한 명을 필수로 둡니다.** 공용이라
  깨지면 여러 앱이 함께 멈춥니다.
- **`hub/places/write.py` 와 `egress.py` 는 특히 봅니다.** 앞은 노션 811줄에 쓰는
  유일한 곳이고, 뒤는 밖으로 나가는 유일한 길입니다. 앞이 잘못되면 팀원이 몇 주간
  손으로 적은 것이 지워지고, 뒤가 잘못되면 우리 IP 가 저쪽 로그에 남습니다.

### 브랜치

- `main`은 항상 돌아가는 상태로 둡니다.
- 각자 `feat/...` 브랜치에서 작업한 뒤 PR로 합칩니다. 자기 앱은 가볍게, 공용은
  리뷰를 받고 머지합니다.

### 비밀 관리 (가장 중요)

- 여섯 저장소가 지금 전부 공개 상태입니다. **조직으로 옮기면서 비공개로 돌립니다.**
- 조직 설정에서 **Secret scanning과 Push protection을 켭니다.** 토큰을 실수로 올릴
  때 GitHub이 막아 줍니다.
- 토큰 읽는 방식을 `NOTION_TOKEN_FILE` 하나로 통일합니다. 지금은 두 방식이 섞여
  있습니다. 파일 방식이 더 안전합니다.
- **크롤러 컨테이너에는 노션 토큰을 넣지 않습니다.** 크롤링 계획서 §4.1 그대로입니다.
  Notion-DLS가 이미 VM과 호스트를 나눠 두었으니 그 방식을 표준으로 삼습니다.
- `.env`는 커밋하지 않습니다. 값이 빠진 `.env.example`만 올립니다.

### 실행 위치

저장소는 코드만 관리하고, 실제 실행 위치는 나눕니다.

- **오픈웹을 쓰는 것**(ransomware.live, Discord 알림)은 GitHub Actions 스케줄로
  돌려도 됩니다.
- **Tor를 타는 것**(포럼 크롤러, onion 접속)은 Actions에서 돌리지 않습니다. GitHub
  서버가 다크웹에 붙는 셈이라 규정에 걸리고 토큰도 노출됩니다. 팀 서버나 각자 VM에서
  돌립니다.

### 할 일 관리

Issues에 쌓고 라벨로 앱을 구분합니다(`app:forum`, `pkg:telegram` 등). 누가 무엇을
고도화하고 있는지 한눈에 보이게 합니다.

## 6. 마스킹 점검 (옮기기 전 필수)

세 저장소의 README에 스크린샷이 올라가 있습니다. 비공개로 돌리더라도, 옮기기 전에
아래를 확인합니다.

- **Kr-Leak-alarm** 대시보드 스크린샷에 피해 기업 실명이 있는지. (앞서 22쪽 마스킹
  때 이 화면에서 실명 여러 줄이 나온 적이 있습니다.)
- **Notion-DLS** README의 구조도·화면에 onion 주소나 도메인이 있는지.
- **darknetzzzz_telegram**의 AWS 배포 스크립트에 웹훅 URL이나 자격 증명이 박혀
  있는지.

원본에서 가려야 합니다. 비공개로 돌리는 것만으로는 커밋 기록에 남은 것이 지워지지
않습니다.

## 7. 넘어가기 전에 정할 것

- **`collect_messages.py` 두 판 중 어느 쪽이 최신인가.** `dc-telegram`으로 합치려면
  이수빈·성민서 두 분이 먼저 정해야 합니다.
- **노션 DB 스키마를 코드로 굳힐 수 있는가.** 다크웹 DB 칸과 유출 사고 DB 칸이
  확정 상태면 `dc-notion`에 스키마를 한 파일로 넣을 수 있습니다.
- **비공개 전환에 팀 합의가 되는가.** 지금 공개된 것을 비공개로 돌리는 결정입니다.
