고침 2026-08-30

장애가 났을 때 어디를 봐야 하는지 찾기 위한 문서입니다.

---

## 1. 한 줄 요약

```
스케줄러 → dc.py auto → (명부 조사 · 사건 수집) → 노션
```

둘 다 차례가 된 것만 실행합니다. 무엇이 언제 도는지는 `hub/sched.py` 의 SQLite
표가 정합니다.

## 3. 여섯 단계

세 갈래가 동일한 흐름을 거칩니다. 갈래별 차이는 `run.py` 의 `갈래표` 네 칸에만
존재합니다.

| 단계 | 내용 | 파일 |
|---|---|---|
| ① | 조사 대상 선별 | `hub/places/write.py` · `backoff.py` |
| ② | 외부 접속 | `egress.py` |
| ③ | 페이지 열기 | `fetch.py` |
| ④ | 항목 추출 | `probe/` · `collect/` · `extract/` |
| ⑤ | 결과 병합 | `merge.py` |
| ⑥ | 노션 기록 | `hub/places/write.py` |

```python
갈래표 = {
    "forum":  {"여는법": _포럼_열기,  "앞선것": None,        "동시": None, "마지막": dict},
    "ransom": {"여는법": _랜섬_열기,  "앞선것": _랜섬_앞선것, "동시": None, "마지막": dict},
    "telegram": {"여는법": _텔레그램_열기, "앞선것": None,   "동시": 1,    "마지막": list},
}
```

갈래가 늘어도 이 표에 한 줄만 추가합니다.

## 4. 여는 법 세 가지

`fetch.py` 가 세 가지를 갈아 끼웁니다. 호출하는 쪽은 어느 방식인지 알 필요가
없습니다.

| 법 | 수단 | 용도 |
|---|---|---|
| `http` | urllib | 기본값. 대부분의 조사 |
| `browser` | Playwright + Chromium | 수집기 7종 실행 (page 객체 필요) |
| `api` | 각 서비스 API | 텔레그램 |

### 브라우저의 역할

브라우저는 **차단을 우회하는 수단이 아닙니다.** 2026-08-30 실측 결과입니다.

| 판정 | 포럼 20줄 중 |
|---|---:|
| 둘 다 실패 | 14 |
| 둘 다 성공 | 4 |
| http 만 성공 | 2 |
| **browser 만 성공** | **0** |

클라우드플레어는 헤드리스 크롬을 더 정확히 식별합니다. 「연결이 안 됩니다」의
대부분은 앞단 검사가 아니라 Tor 터널 실패입니다.

따라서 브라우저는 **이미 열린 곳을 더 깊게 보는 용도**로만 사용합니다. 깊은 판은
상태를 갱신하지 않습니다. 브라우저가 403을 받아도 그 사이트가 죽은 것은
아니기 때문입니다.

## 6. 기계가 쓰는 칸 18개

처리 방식이 셋으로 나뉩니다. 이 구분을 지키지 않으면 사람이 조사한 내용을
기계가 지웁니다.

| 방식 | 대상 칸 | 동작 |
|---|---|---|
| 덮어쓰기 | 상태 · 확인일 · 주소 · 어니언 주소 · 최근 활동 | 조사할 때마다 새 값 |
| 병합 | 규모 · 피해 대상 · 한국 관련 유출 | `(YYYY-MM-DD 기준)` 으로 끝나는 기계 줄만 교체 |
| 빈칸 한정 | 가입 필요 · 개인정보 유출 · 들어가는 법 · 사용 언어 · 어떤 곳인지 · 연결된 곳 · 연락수단 · 유통 자리 · 이전 이름·별칭 · 이전 주소 · 조사 단계 · 종류 · 출처 · 형식 | 사람이 입력한 경우 유지 |

`압수됨` 과 `인계됨` 은 기계가 덮어쓰지 않습니다. 「살아있는가」가 아니라
「무슨 일이 있었는가」이므로 사람이 판정합니다.

### 근거 기반 항목

「유통 자리」와 「개인정보 유출」은 포럼이 스스로 표기한 게시판 이름에서
추출합니다(`places/extract/boards.py`). 추측이 아니라 대상이 기재한 내용입니다.

**게시글 제목은 읽지 않습니다.** 유출 글 제목에는 피해 기업명이 포함됩니다.
근거가 없으면 해당 칸을 비워 둡니다.

「연결된 곳」은 첫 화면 링크 중 **명부에 이미 등재된 곳**만 기록합니다
(`places/extract/links.py`). 미등재 주소는 관계가 아니라 잡음입니다.

## 7. 기계가 쓰지 않는 칸

| 칸 | 이유 |
|---|---|
| 담당자 · 순위 · 웹에 올림 · DB 반영 · 일부러 반출하지 않음 | 팀 운영 항목. 조사 결과가 아님 |
| 비고 | 「왜 그렇게 판단했는지」를 사람이 기재 |
| 국가 | 아래 참조 |

### 국가를 쓰지 않는 이유

`추정: ` 접두어가 붙은 선택지가 **랜섬웨어 DB에만 존재합니다.**

```
ransom     … · 추정: 러시아 · 추정: 중국 · 추정: 독일
forum      없음
telegram   없음
```

포럼과 텔레그램에서는 추정을 추정으로 표시할 방법이 없습니다. 선택지를 늘리지
않기로 했으므로 비워 둡니다. 811줄이 전부 비어 있으나, 근거 없는 값보다 빈 칸이
낫습니다.

언어로 추정하는 방법도 성립하지 않습니다. 영어 포럼은 어디에나 있고 러시아어는
러시아어권이지 러시아가 아닙니다. 최상위 도메인도 `.com` · `.cc` · `.to` 가
대부분으로, 방탄 호스팅용이지 국가 표시가 아닙니다.

## 8. 명부와 사건 기록

동일하게 「크롤링」이라 부르지만 채우는 대상이 다릅니다.

| | 명부 `dc.py crawl` | 사건 기록 `dc.py run` |
|---|---|---|
| 채우는 곳 | 다크웹 DB 3개 | 수집·검증 DB |
| 묻는 것 | 어디가 있고 살아있는가 | 무슨 글이 올라왔는가 |
| 한 줄의 단위 | 한 곳 | 한 사건 |

두 경로는 서로의 DB를 건드리지 않습니다.

## 10. 장애 대응

| 증상 | 확인할 곳 |
|---|---|
| 「Tor 가 없어 안 나갔습니다」 | `python dc.py doctor --net`. tor 실행 여부 |
| 「연결이 안 됩니다」 | 백신 · 망 상태. **offline이 아니므로 상태를 변경하지 않음** |
| 「스키마에 없는 칸」 | 노션 칸 이름 변경됨 |
| 「선택지에 없어 안 쓴 값」 | 해당 갈래 DB에 그 select 값 없음 |
| 「압수 안내로 바뀌었습니다」 | 사람이 수동 처리. 포럼 DB에 `압수됨` 선택지 없음 |
| 「아직 때가 안 됐습니다」 | 정상. `주기` 확인 |
| 「깊게 0줄」 | 브라우저 미설치 또는 Tor 부재 |
| 「살아있는 창」 증가 | 브라우저 컨텍스트 누수. `fetch.py` 확인 |
| 바뀐 줄 0 | 이미 동일한 값. 확인일만 갱신하지 않음 |
