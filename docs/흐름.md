# 흐름 — 무엇이 무엇을 부르나

한 판이 어떻게 도는지입니다. 어디가 막히면 어디를 봐야 하는지 알려는
문서입니다.

## 한 줄 요약

    스케줄러 → dc.py auto → (수집기 · 크롤러) → 노션

둘 다 **때가 된 것만** 돕니다. 스케줄러는 자주 부르고, 무엇이 언제 돌지는
차례표(`hub/sched.py` 의 SQLite 표)가 정합니다.

## 그림

```
  cron (VM 안)  30분마다
        │
        ▼
  dc.py auto
        │
        ├── run --due ──────────► hub/runner.py ──► hub/adapters/*.py
        │   수집기. 사건 기록을            │        (ransom-kr · tg-preview)
        │   수집·검증 DB 로                │
        │                                  ▼
        │                            packages/ 공용 부품
        │
        └── crawl --due ────────► hub/crawler/run.py
            명부. 어디가 있고              │
            살아있나                       ├─ 차례가 됐나 (hub/sched.py)
                                           │
                                           ├─ 노션에서 줄들을 읽음
                                           │   hub/crawler/notion.py
                                           │   · 스키마를 읽어 없는 칸을 거름
                                           │   · select 선택지도 읽어 둠
                                           │
                                           ├─ 갈래별 조사기
                                           │   probe/telegram.py
                                           │   probe/forum.py
                                           │   probe/ransom.py
                                           │       probe/_읽기.py  언어 판별
                                           │       probe/_이음.py  연결된 곳
                                           │       │
                                           │       └─ probe/_나가기.py
                                           │           **밖으로 나가는 유일한 길**
                                           │           Tor 가 없으면 안 나감
                                           │
                                           ├─ Place 한 모양으로 (place.py)
                                           │
                                           ├─ 노션에 반영 (notion.py)
                                           │   1. 스키마에 없는 칸 거름
                                           │   2. 사람이 쓴 칸 거름 (빈칸만칸)
                                           │   3. 선택지에 없는 값 거름
                                           │   4. 같은 값이면 안 씀
                                           │
                                           └─ 숫자를 SQLite 에 시계열로 쌓음
```

## 갈래와 주기

| 갈래 | 주기 | 노션 DB | 스키마 |
|---|---|---|---|
| `telegram` | 360분 | 텔레그램 DB | 24칸 |
| `forum` | 720분 | 포럼 DB | 25칸 |
| `ransom` | 720분 | 랜섬웨어 DB | 30칸 |

주기를 고치려면 `hub/crawler/run.py` 의 `주기` 를 고칩니다. 그 값이
차례표에 그대로 쓰입니다.

## 기계가 쓰는 칸 18개

다루는 법이 셋으로 갈립니다. 이 갈래를 안 지키면 사람이 조사한 글을
기계가 지웁니다.

| 다루는 법 | 칸 | 뜻 |
|---|---|---|
| 덮어쓰기 | 상태 · 어니언 주소 · 주소 · 최근 활동 · 확인일 | 기계 소관. 볼 때마다 새 값 |
| 합치기 | 규모 · 피해 대상 · 한국 관련 유출 | `(YYYY-MM-DD 기준)` 으로 끝나는 기계 줄만 갈아 끼움 |
| 빈칸만 | 가입 필요 · 개인정보 유출 · 들어가는 법 · 사용 언어 · 어떤 곳인지 · 연결된 곳 · 연락수단 · 유통 자리 · 이전 이름·별칭 · 이전 주소 · 조사 단계 · 종류 · 출처 · 형식 | 사람이 썼으면 안 건드림 |

「유통 자리」와 「개인정보 유출」은 포럼이 스스로 붙인 게시판 이름에서
나옵니다(`probe/_게시판.py`). 우리 추측이 아니라 그 쪽이 적어 둔 것입니다.
**게시글 제목은 안 읽습니다** — 유출 글 제목에는 피해 기업 이름이
들어갑니다. 증거가 없으면 그 칸을 아예 안 씁니다.

「상태」가 이미 `압수됨`·`인계됨` 이면 기계가 안 덮습니다. 그것은
「살아있나」 가 아니라 「무슨 일이 있었나」 라서 사람이 판정한 값입니다.

갈래마다 있는 칸이 다릅니다. 「연락수단」·「피해 대상」·「최근 활동」은
랜섬웨어 DB 에만, 「어니언 주소」는 포럼 DB 에만 있습니다. `place.py` 가
갈래를 보고 가르고, `notion.py` 가 스키마로 한 번 더 거릅니다.

「연결된 곳」은 첫 화면의 링크 중 **우리 명부에 이미 있는 곳**만 적습니다
(`probe/_이음.py`). 처음 보는 주소는 관계가 아니라 잡음입니다. 여기서
생태계 지도의 선이 나옵니다.

「조사 단계」는 두드려서 본 줄에 `확인만 함` 을 넣습니다. 사람이 이미
적은 줄은 안 건드립니다. 그래야 「다음에 할 곳」 뷰(조사 단계 = 시작 전)가
한 판에 비지 않습니다.

목록 밖은 아예 안 씁니다. 조사 단계 · 유통 자리 · 비고 · 순위 · 웹에
올림 · 담당자 · DB 반영 · 일부러 반출하지 않음은 사람이 판단하는 칸입니다.

## 명부와 사건 기록이 다릅니다

같은 「크롤링」이라는 말을 쓰지만 채우는 곳이 다릅니다.

| | 크롤러 (`dc.py crawl`) | 수집기 (`dc.py run`) |
|---|---|---|
| 채우는 곳 | 다크웹 DB (포럼·텔레그램·랜섬) | 수집·검증 DB |
| 묻는 것 | 어디가 있고 살아있나 | 무슨 글이 올라왔나 |
| 한 줄 | 한 곳 | 한 사건 |
| 주인 | 통합 크롤러 | 최현서 님 구상 |

크롤러가 수집·검증 DB 를 건드리지 않습니다. 반대도 마찬가지입니다.

## 깊은 조사와 가벼운 확인

같은 대상을 두 도구가 봅니다. 겹치면 안 됩니다.

| 갈래 | 가벼운 확인 (자주) | 깊은 조사 (가끔) |
|---|---|---|
| 포럼 | `hub/crawler/probe/forum.py` 첫 화면만 | `apps/forum-crawler` 도커·로그인 |
| 랜섬 | `probe/ransom.py` `/groups` 한 번으로 상태 | `apps/dls-observatory/dls_fill.py` 그룹마다 조회 |
| 텔레그램 | `probe/telegram.py` 공개 미리보기 | `skills/collect` 실계정 |

랜섬 갈래에서 피해 집계를 껐습니다. `dls_fill` 이 이미 그 칸들을
채우는데 꼴이 달라 서로 갈아 끼우지 못하고 줄이 쌓였습니다.

## 막혔을 때 어디를 보나

| 증상 | 볼 곳 |
|---|---|
| 「Tor 가 없어 안 나갔습니다」 | `dc.py doctor --net`. tor 가 떠 있나 |
| 「연결이 안 됩니다」 | 백신·망. **offline 이 아닙니다.** 상태를 안 바꿉니다 |
| 「스키마에 없는 칸」 | 노션 칸 이름이 바뀌었습니다 |
| 「선택지에 없어 안 쓴 값」 | 그 갈래 DB 에 그 select 값이 없습니다. 포럼·텔레그램에는 `압수됨` 도 `직접 확인` 도 없습니다 |
| 「압수 안내로 바뀌었습니다」 | 사람이 손으로 처리할 것입니다. 포럼 DB 에 `압수됨` 선택지가 없습니다 |
| 「아직 때가 안 됐습니다」 | 정상입니다. `주기` 를 보십시오 |
| 바뀐 줄이 0 | 이미 같은 값입니다. 확인일만 바꾸려고 쓰지 않습니다 |

## 점검

```bash
python dc.py doctor --net     # 나가는 길
python dc.py crawl --limit 3  # 미리보기 (노션에 안 씀)
python dc.py plan             # 무엇이 몇 분마다 도는지
```

검사는 `packages/tests/` 에 있습니다. 전부 표준 라이브러리로 돕니다.

```bash
for f in packages/tests/test_*.py; do python "$f"; done
```
