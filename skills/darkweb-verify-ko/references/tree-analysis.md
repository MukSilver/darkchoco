# 파일 트리 분석

확보한 유출물의 구조로 초동 분석을 한다. 파일 내용을 열지 않고 이름과 경로만 본다.

## 왜 다른 재료인가

| | 판매글, 샘플 | 파일 트리 |
|---|---|---|
| 누가 고른 것 | 판매자 | 구조 전체 |
| 조작 난이도 | 쉬움 | 어렵다. 커밋 수백 개와 브랜치 전략을 만들어내기는 어렵다 |
| 값을 봐야 하나 | 봐야 함 | **안 봐도 됨** |

값을 안 봐도 되는 것이 핵심이다. 마스킹 없이 원문 그대로 분석할 수 있다.

## 계상 기준

| 무엇 | 계상 |
|---|---|
| 판매자가 게시글에 올린 트리 캡처 | 게시글 내용이다. 독립 근거로 세지 않는다 |
| 우리가 확보한 실물 트리 | 게시글 밖 사실이다. 계상한다 |

트리는 수집기가 자동으로 가져오지 않는다. 사람이 넣는 입력이다.

## 마스킹

**트리는 마스킹 대상이 아니다.** 값이 아니라 이름과 구조다. 마스킹하면 분석이 망가진다.

파일명 자체에 개인정보가 든 경우 **산출물에 실을 때만** 걸린 부분을 가린다.

가리는 기준이다.

    걸린 부분만 가린다. 첫 글자를 남기고 나머지를 ○ 로 바꾼다
    디렉터리 경로, 확장자, 구분 기호는 그대로 둔다
    가린 자리가 몇 글자였는지 보이게 같은 수만큼 ○ 를 쓴다

## 트리는 축이 둘이다

**하나만 돌리고 끝내지 마라.** 축이 달라서 서로 못 보는 것이 있다.

| 축 | 무엇을 보나 | 못 보는 것 | 도구 |
|---|---|---|---|
| 파일 단위 | 파일명과 경로 | 파일 하나에 든 표 | `tree_scan.py` |
| 표 단위 | 표 이름과 칸 이름 | 파일 배치, 값의 실재 | `db_tree.py` |

### 무엇을 돌리나

| 받은 것 | 돌릴 것 |
|---|---|
| 파일 경로 목록만 | 파일 단위 |
| SQL 덤프 | **둘 다.** 파일 목록으로 한 번, 표 구조로 한 번 |
| CSV 로 뽑힌 표 | 파일 단위 + `sample_stats` 의 칸 이름 절 |
| 압축 안에 SQL 여럿 | 둘 다 |

**피해 범위는 표 하나로 정하지 마라.** 받은 데이터의 표를 전부 훑고
대상 조직 밖 사람의 정보가 든 표가 있는지 본다.

### 등급을 합치지 마라

**하나로 합치면 둘 다 틀린다.** ⑤ 재료 합치기에 두 줄로 적는다.

    자산 민감도 (파일 단위)   치명 n · 높음 n · 중간 n · 낮음 n · 미분류 n
    자산 민감도 (표 단위)     치명 n · 높음 n · 중간 n · 낮음 n · 미분류 n

⑧ 위험도의 자산 민감도는 **둘 중 높은 쪽**이다.
표 하나가 치명이면 파일 단위가 미분류여도 치명이다.

### 두 축이 어긋날 때

파일 단위가 낮은데 표 단위가 높게 나오는 것은 **정상이다.**
고치려 들지 말고 두 값을 그대로 적는다.

어긋난 이유를 ⑤ 에 한 줄 붙인다. 어느 표가 등급을 올렸는지 적는다.

## 도구

    python tools/tree_scan.py <트리파일> --md 출력.md
    python tools/db_tree.py <덤프.sql> --md 출력.md

`db_tree.py` 는 칸 이름과 건수만 읽는다. 값을 출력하지 않는다.

입력 형식은 아래를 받는다.

    한 줄에 경로 하나
    tree 명령 출력 (가지 문자 포함)
    unzip -l, find, git ls-files 출력

규칙은 `tools/tree_rules.json` 에 있다. 코드와 분리돼 있어 패턴만 추가하면 된다.

## 자산 민감도 등급

| 등급 | 무엇 | 파일명 신호 |
|---|---|---|
| 치명 | 즉시 악용 가능한 자격증명 | .git/config, .env, .npmrc, id_rsa, *.pem, *.p12 |
| 높음 | 내부 접근 경로 | *.tf, *.kubeconfig, docker-compose*, 설정 파일 안의 사내 URL |
| 높음 | 개인 식별 | 실명·이메일이 든 파일명, 커밋 작성자, CODEOWNERS |
| 중간 | 사내 소스 | package.json 의 private true, 사내 스코프 패키지 |
| 중간 | 업무 맥락 | 커밋 메시지의 티켓 번호, 브랜치명 |
| 낮음 | 공개돼도 무해 | README, LICENSE, 락파일 |

**등급을 하나로 합치지 않는다.** 치명 1건과 중간 500건은 성격이 다르다.
등급별 건수를 그대로 낸다.

DB 덤프는 표 단위로 따로 매긴다. `db_tree.py` 가 낸다.

| 등급 | 무엇 | 칸 이름 신호 |
|---|---|---|
| 치명 | 관리자 자격증명 | `master_pwd`, `admin_pw`. 표 이름이 관리자 계열이고 비밀번호 칸이 있을 때도 |
| 높음 | 주민번호 칸 | `jumin`, `ssn`, `rrn` |
| 높음 | 카드·금융 | `card`, `bank`, `account_no` |
| 높음 | 비밀번호 | `passwd`, `pwd`, `pws` |
| 높음 | 신원 2종 이상 | 이름·이메일·전화·주소 중 둘 이상 |
| 중간 | 신원 1종, 결제·주문 이력, 계정 아이디 | |
| 낮음 | 공개 데이터 | 우편번호 표 |
| 미분류 | 개인정보 칸 없음 | |


### 치명은 시스템 접근으로 가른다

파일 단위 치명 12개의 공통점은 개인정보의 양이 아니다.
**그 값으로 어딘가에 들어갈 수 있느냐**다.

| 무리 | 예 |
|---|---|
| 시스템 계정 | AD 데이터베이스, 레지스트리 하이브, 리눅스 비밀번호 |
| 인프라 접근 | git 설정, 클라우드 자격증명, 환경변수 파일, 서비스 계정 키 |
| 신원 위조 | 개인키, 인증서 개인키 |
| 관리자 자격 | 비밀번호 금고, 무인 설치 응답 파일 |

표에도 같은 축을 쓴다.

| 무엇 | 등급 | 왜 |
|---|---|---|
| 관리자·운영자 계정의 자격증명 | **치명** | 그 시스템의 운영 권한이다 |
| 결제·정산 연동 키 (PG 가맹점 ID, API 키) | **치명** | 돈이 오가는 시스템에 붙는다 |
| 그 밖의 계정 자격증명 | **높음** | 그 시스템의 운영 권한이 아니다. **건수가 많아도 높음이다** |
| 신원 정보 (이름·전화·주소) | 높음 | |

### 어느 축에 넣나

같은 사실이 두 축에 걸린다. 어디에 넣을지 헷갈리면 아래를 본다.

| 사실 | 자산 민감도 | 즉시 악용 가능성 |
|---|---|---|
| 관리자 자격증명이 있다 | 치명 | |
| 그 값이 평문이다 | **안 바꾼다** | 가능 |
| 그 값이 해시다 | **안 바꾼다** | 조건부 |
| 관리자가 아닌 계정의 자격증명이 많다 | 높음 | 건수만큼 올린다 |

**평문이냐 해시냐로 자산 민감도를 올리지 마라.** 두 축이 섞이면
같은 성격의 유출이 케이스마다 다르게 매겨진다.

관리자가 아닌 계정은 비밀번호가 몇 건이든 자산 민감도가 높음이다.
위험이 작다는 뜻이 아니라 즉시 악용 가능성과 피해 범위에서 잡힌다는 뜻이다.

### 칸이 있는 것과 값이 든 것

**등급은 칸 이름으로 매긴다.** 값이 비어 있어도 안 내린다.

주민번호 칸이 있다고 도구가 알리면 **그대로 받아 적고 확정은 미룬다.**
`sample_stats --table <표>` 로 채움률을 본 뒤 사람이 정한다.
칸 존재와 값 존재를 한 문장에 섞어 쓰지 마라.
2차 자료가 유출됐다고 적어도 값이 0건이면 그 사실을 따로 적는다.

## 진위 신호

경로에서 나오는 것만 자동으로 잡힌다.

| 신호 | 무엇을 뒷받침하나 |
|---|---|
| 사내 전용 패키지 스코프 | 공개 오픈소스가 아님 |
| 업무 티켓 번호 | 정상 업무 프로세스 |
| 릴리즈 태그 | 정상 릴리즈 프로세스 |
| 브랜치 전략 (release, hotfix, feature) | 실제 운영 서비스 |

## 기존 검증 항목에 붙는 자리

새 체계를 만들지 않는다. 핵심 4항목과 보조 7항목에 얹는다.

| 항목 | 트리에서 나오는 근거 |
|---|---|
| 대상 일치 | 사내 전용 패키지 스코프, 내부 URL 도메인, 커밋 작성자 이메일 도메인 |
| 샘플 검증 | 실물 트리는 샘플보다 강한 증거. 구조 전체는 부분 위조가 어렵다 |
| 내용 일치 | 주장 항목이 실제 파일 구성에 있는가 |
| 규모 검증 | 파일 수, 용량, 커밋 수와 대조 |
| 형식 (보조) | 파일 구조가 그 조직 기술 스택과 맞는가 |
| 중복 (보조) | 파일 목록을 해시로 만들어 과거 유출과 대조 |
| 원천 (보조) | 정상 릴리즈 프로세스 흔적. 티켓 번호, PR, 태그 |
| 유통 (보조) | 같은 핸들이 무관한 조직에도 같은 형식으로 올렸는가 |
| 피해성 (보조) | 위험도 다섯 항목 |

## 위험도로 넘어가는 자리

| 위험도 항목 | 트리에서 |
|---|---|
| 자산 민감도 | 등급별 건수. **파일 단위와 표 단위 중 높은 쪽** |
| 즉시 악용 가능성 | 자격증명 파일 유무 |
| 신선도 | 커밋 최신 날짜, 파일 수정 시각 |
| 피해 범위 | 고객사 식별자, 테넌트 문자열 유무 |
| 확산 정도 | 게시 형태 (무료 공개인지 판매 중인지) |

**피해 범위를 꼭 본다.** 대상 조직 것만인지 그 조직의 고객 데이터가 섞였는지가
피해 파장을 통째로 바꾼다.

## 하면 안 되는 것

**토큰이나 자격증명이 보여도 살아있는지 확인하려고 요청을 보내지 않는다.**
남의 자격증명을 실제로 쓰는 행위다. 존재와 패턴까지만 기록한다.

**유출 파일을 내려받지 않는다.** 다운로드 링크는 존재만 기록한다.

## 못 봄으로 적을 것

트리 분석으로는 확인할 수 없는 것들이다. 빈칸으로 두지 않는다.

    자격증명 값      파일 내용을 열지 않아 확인 못 함
    토큰 유효성      확인하지 않음. 하지 않는 행위다
    파싱 실패 줄     입력에서 경로로 못 읽은 줄 수
