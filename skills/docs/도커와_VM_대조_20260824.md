# 도커에서 무엇이 달라지나

VM 공유폴더에서 정리한 위협 목록을 컨테이너에 나란히 놓고 대조한 것이다.
2026-08-24. 실행 옵션은 README 의 도커 절 기준이다.

**한 줄로 말하면 다섯 중 넷은 같거나 낫고, 새로 생기는 것이 셋이다.**

---

## 이미 알던 다섯

| 위협 | VM 공유폴더 | 컨테이너 |
|---|---|---|
| 경로 탈출 (`..`, 절대경로) | 호스트로 나간다 | **`/out` 으로만 나간다.** 재료는 `:ro` 라 못 쓴다 |
| 심볼릭 링크 | 링크를 따라 VM 밖으로 | **컨테이너 안에 갇힌다.** 마운트 네임스페이스가 다르다 |
| 압축 폭탄 | VM 디스크가 찬다 | **막지 못한다.** 아래를 본다 |
| 프롬프트 인젝션 | 같다 | 같다. 격리로 막는 것이 아니다 |
| 확장자 위장 | `inspect.py` 가 잡는다 | 같다 |

심볼릭 링크는 **컨테이너 쪽이 낫다.** `/data/link -> /etc/passwd` 가 있어도
컨테이너의 `/etc/passwd` 를 가리킨다. 호스트 파일이 아니다.

경로 탈출도 절반은 막힌다. 재료를 `:ro` 로 붙이므로 거기에는 못 쓴다.
다만 `/out` 은 쓰기 가능이고 그건 호스트 폴더다.

### 압축 폭탄만 남는다

`--memory 2g` 와 `--pids-limit 128` 이 메모리와 프로세스는 막는다.
**디스크는 못 막는다.** bind mount 에는 `--storage-opt` 가 안 먹는다.

`/out` 이 차면 호스트 디스크가 찬다.

그래서 규칙이 그대로다. **압축은 컨테이너에서 풀지 않는다.**
`inspect.py` 는 이미 풀린 폴더만 본다. 푸는 것은 VM 에서 하고,
컨테이너에는 텍스트로 확인된 것만 넣는다.

---

## 새로 생기는 셋

### 하나. 커널을 함께 쓴다

VM 은 커널이 따로다. 컨테이너는 호스트 커널을 그대로 쓴다.
**커널 취약점이면 격리가 통째로 무너진다.**

`--cap-drop ALL` 과 `--security-opt no-new-privileges` 가 표면을 줄이지만
없애지는 못한다. 이건 옵션으로 못 고치는 성질이다.

윈도우에서 Docker Desktop 을 쓰면 컨테이너가 WSL2 안에서 돈다.
**그 경우에는 VM 이 한 겹 더 있는 셈이라 오히려 낫다.**
다만 bind mount 를 윈도우 경로로 잡으면 그 통로는 그대로 열린다.

### 둘. 이미지가 공급망이다

`python:3.12-slim` 을 받아 온다. VM 은 우리가 깐 것이고 이건 남이 만든 것이다.

우리는 `pip install` 을 안 하므로 그 층은 없다.
**베이스 이미지 한 겹만 남는다.**

제3자에게 나갈 것이면 태그 대신 다이제스트로 고정하는 편이 낫다.

    FROM python:3.12-slim@sha256:<...>

태그는 같은 이름으로 내용이 바뀐다. 다이제스트는 안 바뀐다.
우리 쪽은 태그로 두고, 쓰는 사람이 고정하고 싶으면 그렇게 하면 된다.

### 셋. 도커 소켓을 붙이면 끝난다

    -v /var/run/docker.sock:/var/run/docker.sock     ← 절대 붙이지 마라

붙이는 순간 컨테이너 안에서 호스트에 루트로 컨테이너를 띄울 수 있다.
격리가 있으나 마나가 된다.

우리 README 예제에는 없다. 다만 **제3자가 예제를 고칠 수 있으므로 적어 둔다.**

---

## VM 에 있는데 컨테이너에 없는 것

**스냅샷이 없다.**

VM 은 스냅샷을 찍고 되돌린다. 컨테이너는 `--rm` 으로 매번 새로 뜨지만
**bind mount 는 안 되돌아간다.** `/out` 에 무엇이 써졌는지는 사람이 봐야 한다.

컨테이너 안이 더러워지는 것은 걱정할 필요가 없다. 나가면 사라진다.
걱정할 곳은 붙인 두 폴더뿐이다.

---

## 그래서 바꾼 것

| | |
|---|---|
| `--read-only` 와 `--tmpfs /tmp` 추가 | 컨테이너 파일시스템에 아예 못 쓰게 |
| 도커 소켓 경고 | README 에 한 줄 |
| 다이제스트 고정 안내 | README 에 한 줄 |

`--read-only` 를 붙이면 `/tmp` 도 막힌다. `verify_cfg.py` 가 설정을
`DARKCHOCO_CONFIG=/tmp/verify_config.json` 에 쓰므로 `--tmpfs /tmp` 를 함께 준다.

---

## 결론

**컨테이너는 VM 을 대신하지 않는다.** 이 문장이 README 와 Dockerfile 머리에 이미 있고
그대로 맞다.

컨테이너가 맡는 자리는 **텍스트로 확인된 재료를 도구에 태우는 구간**이다.
처음 여는 일, 압축 푸는 일, 실행 파일을 만지는 일은 VM 에서 한다.

그 경계를 지키면 컨테이너 쪽이 더 편하고 몇 가지는 더 안전하다.
경계를 넘기면 커널 하나로 이어져 있어서 VM 을 쓴 의미가 사라진다.
