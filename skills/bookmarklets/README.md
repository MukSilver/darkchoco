# 북마클릿

브라우저 주소 칸에 넣어 쓰는 수집 도구다. 사람이 연 페이지에서 누른다.
스킬이 부르지 않는다. `skills/darkweb-verify-ko/tools/` 의 파이썬과 별개다.

## 킷은 둘이다

하는 일이 갈린다. **어느 페이지에서 무엇을 하려는지**로 고른다.

| 파일 | 크기 | 어디서 | 담긴 모듈 |
|---|---|---|---|
| `darkchoco_포럼_kit.bookmarklet.txt` | 40,833자 | MyBB·XenForo 포럼 | 포럼 · 구조 진단 |
| `darkchoco_조사_kit.bookmarklet.txt` | 31,956자 | 유출 사이트 · 열린 디렉터리 · 증거 사진 | 킬린 · 디렉터리 · 증거 사진 · 구조 진단 |

**케이스 검증에 쓰는 것은 포럼 킷이다.** ② 재료가 거기서 나온다.

`구조 진단` 은 양쪽에 다 들어 있다. 판정이 안 될 때의 받침이라 뺄 수 없다.

### 2026-09-22 에 셋에서 둘로 줄였다

전에는 킷이 셋(`검증`·`조사`·`전부`)이고 낱개 `.txt` 가 다섯 더 있어 **산출물이
여덟**이었다. 무엇을 북마크에 넣어야 하는지가 매번 헷갈렸다.

`전부` 판이 73,767자여서 주소 칸 한계 60,000 을 넘는 유일한 파일이었다.
그것을 없애고 나머지 둘의 이름을 하는 일에 맞췄다. **지금 둘 다 한계 아래다.**

낱개 `.txt` 다섯은 통합본이 잘릴 때의 폴백이었는데, 잘릴 것이 없어져 쓸모가
없어졌다. 지웠다. 만들 일이 있으면 경로를 직접 주면 된다 (아래 「고친 뒤」).

## 파일이 열다섯인데 쓰는 것은 둘이다

역할이 넷으로 나뉜다.

| 역할 | 파일 | 개수 | 언제 |
|---|---|---|---|
| **북마크에 넣는 것** | `darkchoco_*_kit.bookmarklet.txt` | 2 | 평소 |
| 중간 산출물 | `darkchoco_*_kit.js` | 2 | 안 건드린다 |
| 소스 | `.js` 여섯 | 6 | 고칠 때 |
| 빌더 | `build_*.py` 셋 | 3 | 고친 뒤 |

나머지 둘은 이 문서와 `설치.html` 이다.

**소스 여섯은 복사본이 아니라 재료다.** 킷 둘이 그 여섯에서 만들어진다.

    forum_kit.js ────────────────────────────→ darkchoco_포럼_kit.js
    probe_generic.js ─┬──────────────────────↗
                      │
    qilin_kit.js ─────┼──┐
    index_kit.js ─────┼──┼─ build_kit.py ───→ darkchoco_조사_kit.js
    photo_kit.js ─────┘  │
    kit_shell.js ────────┘

    darkchoco_*_kit.js  ──→ build_bookmarklet.py ──→ .bookmarklet.txt

지우면 킷을 다시 못 만든다. `forum_kit` 이 소스를 잃어 압축본에서 복구한 적이 있다.

**`darkchoco_*_kit.js` 를 손으로 고치지 마라.** `build_kit.py` 가 만든 것이라
다시 빌드하면 덮어쓴다.

## 눌렀을 때

### 포럼 킷

바로 상자가 뜬다. **고르는 판이 없다.** 담긴 모듈이 하나뿐이기 때문이다.
구조 진단은 그 상자 안에 단추로 이미 있어서 판이 한 겹 더 있을 뜻이 없다.

#### 결과를 둘로 가른다 (v2.8 · 2026-09-23)

돌리고 나면 둘째 줄의 단추 셋으로 결과를 내보낸다. **원문과 칸 값을 가른다.**

    원문 저장 (.md)                결과 상자의 원문을 이 PC 에 파일로. 서버로 안 간다
    대시보드로 보내기 (호스트)       칸 값을 대시보드 「포럼 사건 올리기」 로 넘긴다
    칸 파일 저장 (VM)              칸 값을 .json 으로 저장한다. 대시보드에 끌어다 놓는다

**칸 값에는 본문이 없다.** 제목 · 주소 · 게시자 · 날짜 · 게시판과, 원문에서 본 한국
신호(.kr 도메인 · 한글이 있었나 · Korea 낱말이 있었나)뿐이다. 이메일 · 전화 같은 값은
안 들어간다.

**킷은 노션에 직접 쓰지 않는다.** 킷은 포럼 페이지 안에서 돌고, 그 페이지는 믿을 수
없는 곳이다. 대시보드가 칸 값을 미리 보이고 **사람이 「올리기」 를 누를 때만** 수집 DB 에
미검토 · 공개 꺼짐으로 들어간다. 같은 글이 이미 있으면(UID 나 원문 주소가 같으면) 새로 안 만든다.

**대시보드 주소는 레포에 없다.** 설치 페이지의 「대시보드 주소」 칸에 적은 뒤 끌어다 놓으면
그 사람 북마크에만 들어간다. 안 적으면 「대시보드로 보내기」 가 칸 값을 클립보드에 복사하고,
대시보드 「포럼 사건 올리기」 에 붙여 넣으면 된다. VM 안 브라우저에서는 비워 두고 칸 파일을 쓴다.

#### 체크한 게시판 훑기 (v2.9 · 2026-09-29)

미리 체크해 둔 게시판들의 글 목록을 단추 하나로 차례로 받는다. **자동 감시가 아니다.** 사람의 브라우저와
로그인으로 돌고 글 본문은 안 연다. 결과 꼴은 「글 목록」 과 같아서 `kit_in.py` 가 그대로 읽는다.

    이 게시판 체크     글 목록 쪽에서 켜면 이 게시판이 목록에 들어간다(20곳까지)
    체크 목록          결과 상자가 편집기가 된다. 한 줄에 「이름 ⇥ 주소」. 이 호스트 주소만 받고 위험 링크는 버린다
    훑기 쪽 수         게시판마다 1~3쪽
    체크한 게시판 훑기  요청 수와 걸릴 시간을 먼저 묻고 시작한다

- **간격은 하한 5초, 기본 5~10초다.** 요청 간격 칸이 더 크면 그 값을 쓴다
- **429 · 503 · 챌린지 화면이면 그 자리에서 전부 멈춘다.** 403 · 404 · 1쪽 0건은 그 게시판만 건너뛰고,
  두 곳이 잇달아 실패하면 전부 멈춘다(로그인이 풀렸을 수 있다)
- 지난 훑기 뒤 처음 본 글에 「[새]」 가 붙는다. 게시판마다 **글 주소의 해시만** 200개 남긴다. 제목은 안 남긴다
- 목록과 본 글 기록은 이 브라우저의 localStorage 에만 있다. Tor 브라우저는 창을 닫으면 지우므로
  「체크 목록」 을 복사해 두었다가 붙여 넣어 되살린다

### 조사 킷

오른쪽 위에 작은 판이 뜬다. **판정된 것이 초록으로 켜져 있다.**

    킬린 · 디렉터리 · 증거 사진 · 구조 진단

판정이 틀렸으면 다른 것을 누르면 된다. 고른 것이 자기 상자를 만들고 작은 판은
사라진다. **한 번에 하나만 뜬다.** 「홈으로」 를 누르면 판으로 돌아간다.

모듈 하나가 멈춰도 나머지는 멀쩡하다. 멈추면 무엇이 멈췄는지 적어 보여준다.

각 모듈은 따로 쓰던 킷의 본문 그대로다. **동작이 바뀌지 않았다.**

## 처음 쓸 때

`설치.html` 을 브라우저로 열어 단추를 **북마크 도구모음으로 끌어다 놓는다.**
눌러서는 안 된다. `① 자리 시험` 부터 놓고 아무 페이지에서 눌러 본다.

**Tor Browser 는 보안 수준이 Standard 여야 돈다.** Safer 이상이면 JS 가 꺼져서
눌러도 아무 일이 안 일어난다.

조사 킷의 `디렉터리` 는 **초동분석** 부터 누른다. 요청을 50회로 묶어 3분 안에
끝난다. 너비 우선이라 위쪽 층이 통째로 남으므로 그것만으로 윤곽이 나온다.
등급이 높은 가지를 찾으면 그 주소를 열고 다시 눌러 깊이 들어간다.

    초동분석 3분   요청 50회로 묶어 빠르게
    전체 수집      깊이와 요청상한을 직접 정한다
    이 폴더만      네트워크를 안 쓴다. 지금 화면만 읽는다

## 최소화

다 화면 오른쪽 아래로 접힌다. `최소화` 를 누르면 상자가 줄고 **상태줄과 중단
버튼만 남는다.** 걸어다니는 중에 아래 페이지를 보면서 진행 상황을 확인할 때
쓴다. `펼치기` 로 되돌린다.

## 고친 뒤

`.js` 소스를 고쳤으면 **순서대로** 돌린다.

    python bookmarklets/build_kit.py            소스 → 킷 둘
    python bookmarklets/build_bookmarklet.py    킷 → 북마클릿 한 줄
    python bookmarklets/build_install_page.py   설치 페이지

**순서를 지켜야 한다.** `build_bookmarklet.py` 만 돌리면 옛 킷을 다시 감쌀
뿐인데 화면에는 「만듦」 이라고 찍힌다. 성공처럼 보이는 실패다. 그래서
소스가 킷보다 새것이면 빌더가 경고를 찍는다. 그 경고가 보이면 첫 줄부터 다시 한다.

`node --check` 를 통과해야만 txt 를 쓴다. 실패하면 옛 txt 를 그대로 둔다.
URL 디코드 왕복 검사도 같이 돈다.

소스 하나를 낱개 북마클릿으로 만들 일이 있으면 경로를 직접 준다.

    python bookmarklets/build_bookmarklet.py bookmarklets/qilin_kit.js

인자를 안 주면 킷 둘만 만든다. 낱개는 안 만든다.

## 최소화 도구

`terser` 가 있으면 변수명까지 줄인다. 없으면 줄만 합친다. **없다고 멈추지 않는다.**

    포럼 킷   65,955  ->  40,833
    조사 킷   46,516  ->  31,956

**terser 가 없으면 포럼 킷이 65,955자가 되어 한계를 넘는다.** 그때는 빌더가
「주소 칸에서 잘릴 수 있다」 를 찍는다. 그 경고가 보이면 terser 를 깔고 다시 만든다.

빌드할 때만 쓴다. 검증 파이프라인 안에서 돌지 않고 컨테이너에도 안 들어간다.

**최소화하면 사람이 못 읽는다.** 그래서 소스를 레포에 둔다.
`forum_kit` 이 한동안 소스를 잃었던 것이 그 규칙이 없어서였다.
2026-08-24 에 압축본 안에서 찾아 복구했다.

## 크기

60,000자를 넘으면 주소 칸에서 잘릴 수 있다고 빌더가 알린다.
**그 숫자는 보수적으로 잡은 것이고 실측한 값이 아니다.**

    2026-08-25   겹친 껍데기를 뜯어 61,393 → 57,055자
    2026-09-22   모듈이 커져 통합본이 73,767자.  다시 경고 범위로 들어옴
    2026-09-22   셋을 둘로 갈라 40,833 · 31,956자.  **둘 다 한계 아래**

껍데기를 또 뜯는 것보다 **쓰는 자리에 맞춰 가르는 편이 낫다.** 포럼 조사만
하면 포럼 킷 하나면 되고, 거기에 킬린과 디렉터리를 같이 담을 이유가 없다.

## 공통 껍데기

`kit_shell.js` 에 상자·상태줄·출력칸·버튼 공장·최소화가 들어 있다.
`qilin`·`index`·`photo` 셋이 이것을 쓴다. 셋의 UI 가 63줄 중 53줄이 같았다.

**`forum_kit` 과 `probe_generic` 은 안 쓴다.** 껍데기 모양이 다르다.
`probe_generic` 은 버튼이 하나뿐이고 `forum_kit` 은 최소화 블록이 다르다.
억지로 맞추면 둘 다 고쳐야 해서 그대로 뒀다.

`BUSY` 와 `ABORT` 는 모듈이 들고 있다. 껍데기는 넘겨받은 함수로만 만진다.
모듈 본문의 수집 반복문이 `ABORT` 를 직접 읽기 때문이다.

    /* @shell */
    const S = mkShell({ busy: () => BUSY, setBusy: v => { BUSY = v; },
                        setAbort: v => { ABORT = v; } });

`/* @shell */` 표시를 빌더가 다르게 다룬다.

| 빌더 | 무엇 |
|---|---|
| `build_bookmarklet.py` | 표시 자리에 껍데기를 넣는다. 낱개로 만들 때 혼자 돌아야 한다 |
| `build_kit.py` | 표시를 지우고 껍데기를 맨 앞에 **한 번만** 둔다 |

`kit_shell.js` 는 북마클릿으로 만들지 않는다. 혼자서는 안 돈다.

## 목록은 한 벌뿐이다

킷 목록은 **`build_kit.py` 의 `KITS` 한 곳에** 있다. 나머지 빌더 둘이 그것을
import 한다.

전에는 `build_kit.py` 와 `build_install_page.py` 가 각자 목록을 들고 있었고
`build_bookmarklet.py` 는 폴더 안 `.js` 를 통째로 훑었다. 킷을 늘리거나 줄일
때마다 세 곳을 고쳐야 했고, 한 곳을 빠뜨리면 설치 페이지가 없는 파일을
가리키거나 지운 파일이 되살아났다.

킷을 하나 더 만들려면 `KITS` 에 항목 하나를 더하고 셋을 순서대로 돌리면 된다.
**모듈**을 더하는 것은 다른 일이다 — `MODS` 와 `KO` 와 `HEAD` 의 `guess` 를
같이 봐야 한다.

## 고칠 때 지킬 것

- **`//` 주석을 쓰지 마라.** 한 줄로 합치면 뒤가 통째로 주석이 된다. `/* */` 를 쓴다.
  줄 맨 앞이든 줄 끝이든 빌더가 막는다. `//` 를 만드는 정규식 리터럴도 걸린다
- **요청 간격을 줄이지 마라.** 계정과 회선을 셋이 공유한다.
  포럼은 입력칸에서 바꿀 수 있지만 **하한 2초** 아래로는 안 내려간다
- **429, 503, Cloudflare 문구면 즉시 중단한다.** 403 은 갈래마다 다르다 —
  `index_kit` 은 걷기를 통째로 끝내고, `forum_kit` 과 `photo_kit` 은 「403 접근 권한
  없음」으로 적고 다음으로 넘어간다. **뒤 둘은 그것이 맞다.** 등급 제한으로 못 본 글을
  「확인 못 함」으로 남기는 것이 우리 규칙이다 (2026-09-22 에 실제와 맞춤)
- **누르면 서버에 남는 링크에는 요청을 보내지 마라.** 이 게시판은 평점·구독·
  모더레이션이 링크 한 번(GET)으로 돈다. `forum_kit` 의 `위험링크` 가 그것을 막는다.
  **목록에서 빼는 것과 요청을 안 보내는 것이 같은 규칙이어야 한다** — 전에는 목록에만
  걸려 있어 요청은 그대로 나갔다
- 파일을 받는 것은 `photo_kit` 하나뿐이다. 다른 kit 에 받는 기능을 넣지 마라
- 받는 도구는 개수 상한을 반드시 둔다. 기본을 낮게 잡는다
- **`.txt` 와 `darkchoco_*_kit.js` 를 손으로 고치지 마라.** 둘 다 만들어지는 파일이다.
  고칠 자리는 소스 여섯뿐이다
- **팀원 브라우저 안의 북마크는 못 고친다.** 북마크에는 파일 이름이 아니라 코드가
  들어 있어서, 새 판을 쓰려면 `설치.html` 에서 다시 끌어다 놓아야 한다.
  상자에 뜨는 `VER` 문자열이 어느 판이 도는지 가르는 유일한 표시다.
