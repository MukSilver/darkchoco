# 손으로 확인하는 것 열여섯

시험 마흔아홉 묶음이 도는데도 여기 목록이 따로 있는 까닭은, **시험이 창을 안 띄우고
모델을 안 올리기 때문**이다. 시험이 지키는 것은 자료와 순수 함수이고, 아래는 사람이
눌러 봐야 알 수 있는 것이다.

    python tests/test_bag.py · test_engine.py · test_talkaid.py · test_ui.py

**넘겨주기 전과 exe 를 다시 지은 뒤에 밟는다.** 판정 칸에 O · X · ~ 를 적는다.

이 파일은 2026-09-23 에 만들었다. 전에는 이 목록을 대화로만 주고받아서 다음 세션에
사라졌다. 기능이 늘면 여기에 줄을 더한다.

### 새 PC 가 있어야 하는 넷 — 팀원에게 넘길 때

**같은 PC 에서는 뜻이 없다.** 모델 2.9GB 가 이미 받아져 있어서 첫 실행 흉내가 안 난다.
팀원 PC 나 새 VM 에서 한다.

| | 무엇을 하나 | 무엇이 보여야 하나 | 판정 |
|---|---|---|---|
| 1 | `.venv` 를 지우고 `scripts\run.bat` 을 더블클릭 | 알아서 준비하고 **창이 저절로 뜬다.** 검은 cmd 창은 안 남는다 | |
| 2 | 그 과정에서 멈추는지 본다 | `UnicodeDecodeError: 'cp949'` 가 **안 나야 한다.** 2026-09-23 에 여기서 멈췄고 고쳤다 | |
| 3 | 창이 뜬 뒤 「▸ 로그」를 편다 | 모델 받은 진행률이 쌓여 있다 | |
| 4 | 한국어를 골라 `Ctrl+C` → `Ctrl+Alt+1` → 다른 창에 `Ctrl+V` | 영어가 붙고 창에 역번역이 같이 뜬다 | |

**2번이 가장 중요하다.** 그 버그 때문에 팀원은 `run.bat` 을 눌러도 창을 한 번도
못 봤을 것이다. 고친 뒤 이 PC 에서는 재현이 안 되는 것을 확인했지만,
**남의 PC 에서 처음부터 도는 것은 아직 아무도 안 봤다.**

### 자동으로 밟을 때 걸렸던 것

창 자리가 (206,195) 에서 (5,83) 으로 바뀌어 있어서 화면 절대 좌표로 누르면
빗나갔다. 사이드바 단추가 안 눌리는 것처럼 보였는데 클릭 자체는 멀쩡했다.
**`GetWindowRect` 로 창 자리를 매번 다시 재고 창 기준 좌표로 눌러야 한다.**
스크래치패드의 `눌러보기.ps1` 이 그렇게 한다 — 휠도 된다 (`-Wheel -10`).

## 자동으로 못 보는 까닭

| 항목 | 왜 시험이 못 잡나 |
|---|---|
| 1~3 | venv 와 모델 내려받기는 시험이 안 건드린다 |
| 4~6 | `RegisterHotKey` 는 실제 창이 있어야 걸린다 |
| 7~9 | 모델을 올려야 한다. 시험은 400ms 와 인터넷을 아끼려고 안 올린다 |
| 11~14 | tkinter 창과 클립보드가 필요하다. `test_ui.py` 는 자료 구조만 본다 |
| 16 | 지은 exe 는 레포 밖에 있다 |

**7·8 은 특히 사람이 봐야 한다.** 번역 품질은 시험이 원리상 못 잡는다 — 무엇이
맞는 영어인지 코드가 모른다. 대신 두 문장을 못 박아 두어 **고침이 실렸는지**만
가린다. 옛 출력이 나오면 자료나 코드가 안 실린 것이다.
