다크웹의 포럼 · 랜섬웨어 그룹 · 텔레그램 채널 · 행위자를 유형별 섬으로 묶은 헥사 지도다.
칸이 넓을수록 사건과 활동이 많은 곳이다.

## 여는 법

```
npm install
npm run dev          # http://localhost:3000
npm test             # 반출 검사 + 시험
npm run build        # out/ 에 정적 파일
```

**새 클론은 예시 데이터로 뜬다.** 구운 파일(`src/data/map.json`)이 저장소에 없어서,
`dev` · `build` · `test` 앞에 `tools/ensure_map.mjs` 가 빈 파일을 만든다. 실제 지도를 보려면
아래 「굽기」를 먼저 돌린다.

## 자료가 흐르는 길

    노션 (사람이 판정 · 검토 · DB 반영을 찍는다)
      └ tools/bake.py  ── 반출 검사 ──→  src/data/map.json  ──→  화면
                                          (저장소에 안 들어간다)

**구운 파일은 저장소에 넣지 않는다** (2026-09-25). 공개 지도가 내보내는 것과 같은 자료지만,
공개 저장소의 git 기록에 한 번 들어가면 못 지우고 검색 엔진에 색인된다. 루트 `.gitignore` 의
`data/` 규칙이 막는다.

**화면은 노션을 직접 부르지 않는다.** 구운 파일만 읽는다. 화면에서 노션을 부르면 반출 관문이
사라진다. 원천은 Supabase(`darkchoco-data` 의 `core` · `map`)로 옮길 예정이다 —
`tools/supa.py` · `tools/supa_schema.py` 가 1단계(칸 목록)까지 되어 있다.

### 굽기

```
NOTION_TOKEN_FILE=~/.config/darkchoco/NOTION_TOKEN_산출물.txt npm run bake
```

읽는 DB 는 `~/.config/darkchoco/map_sources.json` 이나 환경변수 `DC_MAP_<KEY>_DS` 로 받는다.
**DB id 를 저장소에 박지 않는다.** 값은 database id 가 아니라 data_source id 다.

    collect · verify                 수집 DB · 검증 DB
    forum · telegram · ransomware    게시처 DB 셋 — 이 줄들이 영토가 된다
    actor                            행위자 DB — 행위자 섬 영토가 된다
    relations                        관계선 DB (없어도 굽는다)
    incident                         유출 사고 DB — 공식 발표 사고 (없어도 굽는다)
    address                          주소 변경 이력 DB — 포럼 옛 · 새 주소를 맞추기 별칭으로 (없어도 굽는다)

**행위자 섬은 행위자 DB 줄에서 만들고, 사건과는 수집 DB 「게시자 핸들」로 잇는다** (2026-09-25
22시 최현서 — 행위자 정보를 받으려면 행위자 DB 를 읽어야 한다). 게시자 핸들은 맞추기 전용이라
밖에 안 낸다. 행위자 DB 에 없는 핸들의 사건은 행위자 영토를 안 만든다. 랜섬웨어 섬 사건의
핸들과, 랜섬 그룹 · 지도에 남은 영토 이름과 같은 핸들은 잇지 않는다. 9/25 낮에 잠시 게시자
핸들로 영토를 만들었다가(#47) 같은 날 밤 되돌렸다.

**행위자 정보 칸을 싣는다** (설계서 4.3.8, 2026-09-26 최현서). 역할 · 국가(선택지), 처음 본 날(날짜),
다루는 것 · 다른 이름(사람이 쓰는 글)이다. 사람이 쓰는 두 칸은 수집 DB · 유출 사고 DB 조직 이름과
겹치면 빼고, 값 훑기를 통과해야 하며, 다른 이름은 핸들 모양(글자 · 숫자 · `_` · `-`, 2~32자)만
싣는다. 9/23 검토가 별칭을 막은 까닭(메모 · 자리표시가 섞임)을 모양 검사로 거른다.

**공식 발표 사고(유출 사고 DB)를 사건으로 넣는다** (설계서 2.4 · 2.5 · 3.2, 2026-09-26 최현서 —
읽어도 된다. 조직명은 지도 어디에도 안 낸다). 공표 시점이 게시 시각, 보도된 유출 위치가 영토다.
위치는 게시처 이름과 그대로 맞거나 랜섬 그룹 유출 사이트(DLS)라고 적혔을 때만 맞춘다. 판정은
확인됨, 규모는 유출 규모 칸의 숫자다. 수집 DB 와 같은 사고는 정본 작업판이 짝지은 사건 번호 표
(`SAME_AS_COLLECT`)와 조직 이름 전체 대조로 뺀다. 조직명 · 보도된 유출 위치 · 보도된 행위자는 맞추기
전용이고 출처 링크 · 메모는 안 읽는다. 사고 시점 · 유출 항목 · 외부 확인 · 출처 종류(선택지)만
싣는다. 2026-09-26 굽기에서 316줄 중 8건이 지도에 올랐다 (정본 9/22 는 9건 — 1건은 그 영토가
지금 지도에서 빠졌다).

**사건마다 위험도 · 연결된 사건 · 사기 의심 표시를 싣는다.** 위험도(설계서 3.10)는 검증 DB
「즉시 악용 가능성」과 유출 항목으로 굽기가 매기고 재료는 안 싣는다 (`score.ts` `riskLevel` 과 같은
규칙). 연결된 사건은 수집 DB 「같은 사건」 두 칸을 사건 번호로 바꿔, 지도에 오른 사건끼리만 잇는다.
「사기 의심」은 칩 없이 필터용 표시다 (2.3). 「랜섬웨어 유출」은 파일 공개가 확인돼야 데이터 게시,
아니면 피해 주장이다 — 정본과 같다 (9/25 판은 반대였다).

**3.12 운영 규칙 가운데 셋을 굽기가 한다.** 노션 줄에 없던 칸을 DB 별로 로그에 남기고(칸이 지워지거나
이름이 바뀌어도 멈추지 않는다), 영토를 정할 수 없는 사건 번호를 「확인필요」로 찍고, 사람이 손으로
고친 사건 값을 `tools/overrides.json` 에서 먼저 쓴다(파일이 없으면 아무 일도 안 한다. 조직명을 적지
않는다 — 공개 레포다).

## 계산 규칙 (정본)

    사건 점수     신뢰 × 규모                         허위는 0
    사건 지수     round(100 × ln(1+Σ사건 점수) ÷ ln(1+섬 최댓값))
    활동도        명부 규모 원자료를 같은 식으로 누른 값. 포럼은 회원 · 게시물 · 스레드
                 지수의 평균(빈 지수는 뺀다). 행위자는 사건 수
    영토 점수     (사건 지수 + 기본점 20) × (0.5 + 활동도 ÷ 200)
    섬 몫         round(800 × S(I)^0.6 ÷ Σ) — 합이 어긋나면 가장 큰 섬에 끝전
    칸 수         섬 안에서 최대 나머지 방식. 0칸이면 1칸

`src/lib/score.ts` 가 전부 한다. 반올림은 엑셀 ROUND 와 같다 (0.5 는 0 에서 먼 쪽).

- **행위자 섬은 같은 사건을 한 번 더 센다.** 지도 사건 수는 한 번씩이다
- **날짜를 대신 넣은 사건**(게시 시각이 없어 관측 시각 · 수집일을 넣은 것)은 점수와 칸에는
  들고, 최근 30일 · 7일 창 · 상태 · 급상승에서는 빠진다
- 영토는 첫 사건이 있는 분기부터 나온다. 사건이 없는 명부 영토는 이번 분기에만 나온다
- **랜섬웨어 활동도 원자료는 약 여섯 달 피해 건수다.** 게시처 DB 규모가 「피해 월평균 M건 (최근 D일)」
  꼴이면 M × D ÷ 30 으로 돌려 옛 「피해 기업 N」 과 같은 단위로 읽는다. 두 꼴이 한 섬에 섞여도
  쉬는 그룹이 활발한 그룹보다 크게 그려지지 않는다 (2026-09-25)

### 관계선

세 화면이 같은 관계를 본다. 지도 위 관계선(설계서 4.2.3), 패널 [연결] 탭(4.3.1 · 4.3.2 · 4.3.8),
관계 탭(4.3.3 · 4.3.6)이다. **건수는 `src/lib/relations.ts` 의 `relationsAt` 하나에서 나온다**
— 설계서 3.9 가 세 화면의 건수가 같아야 한다고 정했다.

- 건수는 기준일에 지도에 든 근거 사건 수다. 근거가 처음부터 없는 관계(명부 「연결된 곳」
  칸에서 만든 것)는 1건으로 센다
- **활동 관계(행위자 → 영토)는 사건에서 만든다.** 노션 관계선 DB 의 활동 줄은 사건에서
  나오는 쌍의 일부라, DB 줄은 번호와 신뢰도만 쓰고 근거는 그 행위자가 그 영토에 올린 사건
  전부로 둔다
- 근거 목록은 날짜 · 판정 · 규모 · 올라온 곳만 보인다. 사건 제목에 피해 조직 이름이 든다
- **근거 사건이 없는 관계선은 명부 「연결된 곳」 원문을 보인다** (설계서 4.3.6, 2026-09-25 최현서).
  두 영토의 그 칸에서 상대 이름이 든 항목만 골라 `note` 로 싣는다. 가해 쪽 주소는 들어도 된다.
  수집 DB 「대상 조직」 이름과 겹치는 항목과 @ · 긴 숫자열이 든 항목은 굽기가 뺀다
- 안 만든 것: 「전체 관계 보기」 스위치(설계서 4.2.7 보류), 근거 사건 보고서 팝업(4.3.4)

### 사건 제목

**노션 자료 제목은 안 싣는다.** 피해 조직 이름이 들어 있다. 제목은 분류 칸으로 새로 짓는다
(2026-09-25 최현서 결정, `src/lib/events.ts`).

    [KR · 유통 · 2026-05-14 · 255GB]
     국가  산업 분야  게시 날짜   주장 규모

- 국가는 두 글자 부호, 산업 분야는 선택지의 앞 낱말(`유통·이커머스` → `유통`)이다. 기타 · 미확인은 뺀다
- 규모는 「주장 규모」 글에서 숫자와 단위만 뽑는다. 원문은 안 싣는다. 숫자와 단위를 나눠 싣는다 —
  `1.2TB` 를 글자로 두면 값 훑기가 도메인으로 본다
- 사건 종류 칩은 「게시 성격」에서 온다 (설계서 2.3). 「랜섬웨어 유출」은 「카운트다운 표기」가 있으면
  피해 주장, 없으면 데이터 게시다. 「공개된 파일 수」가 비어 있어서다

**겹친 영토 이름에는 도메인 첫 조각을 붙인다.** 「BreachForums (bf.st)」 · 「BreachForums
(breached.su)」는 괄호를 떼면 둘 다 「BreachForums」라 `BreachForums bf` · `BreachForums breached` 로
낸다. 점이 없어 주소가 아니다. 도메인이 없으면 번호로 물러선다.

### 검색

설계서 4.2.2, 피그마 ⑦-10 · ⑦-10a · ⑦-10b · ⑦-10c · ⑦-10d. 계산은 `src/lib/search.ts` 하나다.

- 이름으로 찾는 것은 영토 이름 · 별칭과 행위자 핸들 · 다른 이름뿐이다. 사건과 관계는 찾은 대상에
  딸려 나온다(연관 검색 한 단계). 사건 제목에는 이름이 없다
- **영토 별칭은 지금 안 찾힌다.** 굽기가 별칭을 싣지 않는다(`bake.py` `TERRITORY_KEYS`,
  2026-09-23 검토). 사람이 쓰는 칸이라 자리표시 · 메모 · 다른 핸들이 섞인다. 검색 코드는 별칭이
  실리면 그대로 찾는다. 행위자 다른 이름은 굽기가 핸들 모양 검사를 거쳐 싣고(9/26) 검색도 찾는다
- **피해 대상 묶음은 없다.** 피해 조직 이름을 지도에 안 낸다 (2026-09-23 결정)
- 기준일과 무관하게 전체 기간에서 찾는다. 한 번이라도 지도에 나온 영토만 대상이다. 고른 대상이
  지금 기준일에 안 보이면 보이는 분기로 기준일을 옮기고 안내에 적는다 — 뒤쪽을 먼저 본다
- 행위자를 고르면 주 활동 영토(사건을 가장 많이 올린 곳)로 가서 패널 [사건]을 그 행위자로 거른다.
  사건을 고르면 [사건]에서 그 사건을 강조한다. 둘 다 [사건] 기간 밖이면 기간을 전체로 넓힌다
- 관계를 고르면 관계 탭 ① 상태(4.3.3)다. 중심은 검색어에 걸린 쪽의 상대 영토다
- 전체 결과 화면의 기간 필터는 사건 게시일 · 관계 마지막 본 날에, 신뢰도는 관계에만 건다.
  웹 필터는 없다 — 이 화면은 다크웹뿐이다
- 사건 「상세」는 보고서 팝업(4.3.4)이 아직 없어 지도로 가서 강조한다
- 주 활동 영토는 `src/lib/actors.ts` 가 센다. 행위자 패널 [개요]와 같은 함수다 (검색은 전체 기간,
  패널은 기준일까지)

### 우측 패널

설계서 4.2.4 · 4.3.1 · 4.3.2 · 4.3.8, 피그마 ⑦-1 · ⑦-2 · ⑦-11b. 조립은 `src/lib/panel.ts`, 그리기는
`src/components/DetailPanel.tsx` 다.

- **선택이 없어도 [사건] · [연결] 이 눌린다** (피그마 ⑦-1 「사건 5 · 연결 18」). [사건]은 지도에 있는
  영토 전부의 사건, [연결]은 섬 쌍 요약 전부다. 설계서는 섬 · 영토 탭만 적었다
- 영토 [개요]: 머리글 「랜섬웨어 섬 · 사건 N건 · 활동도 N · 연결된 섬 N」, 활동도 카드에 원자료
  (포럼 회원 N명 · 텔레그램 구독자 N명 · 랜섬웨어 피해 약 N건 (6개월)), 자동 문장은 피그마 ⑦-11b
  꼴 — 「검증된 관계」는 이 영토가 닿은 관계 가운데 신뢰도 확인됨인 것의 수다
- **공식 발표 사고 절** (4.3.2): 이 영토에 올라온 공식 발표 사건 수와 공표일이 가장 늦은 1건
  (공표일 · 규모 · 분류 칸 제목). 조직명은 없다. 그 줄을 누르면 보고서 팝업이 열릴 자리인데
  팝업(4.3.4)이 아직 없어 눌리지 않는다 (`onOpenEvent` 를 넘기면 산다)

## 반출 경계

**피해 조직 이름은 지도에 내지 않는다** (2026-09-23 최현서 결정). 가해 쪽 — 포럼 · 랜섬웨어
그룹 · 텔레그램 채널 · 행위자 DB 에 등록된 행위자 — 는 영토 이름으로 낸다.

**이 결정은 공개 지도(`apps/map`)에만 적용된다.** 비밀번호 뒤 대시보드(`apps/dash`)는 범위
밖이다. 대시보드는 팀 안에서 검토하는 화면이라 사건 제목과 대상 조직을 보인다.

    1. 줄 관문      「DB 반영」이 꺼졌거나 「검토 여부」가 미검토 · 사건 X 면 뺀다
    2. 읽는 칸      ALLOWED_COLS 밖의 칸을 읽으면 멈춘다. 자료 제목 · 원문 URL ·
                   다크웹 주소 · 출처 링크는 DENY_COLS. 대상 조직 · 게시자 핸들 · 조직명 · 보도된 유출 위치 ·
                   보도된 행위자는 대조 전용(MATCH_ONLY_COLS)
    3. 나가는 키    TERRITORY_KEYS · EV_KEYS · RELATION_KEYS 밖의 키가 있으면 멈춘다
    4. 값 훑기      도메인 · @ · 11자리 넘는 숫자열을 찾는다. 관계선 원문(note)만
                   도메인을 허용한다
    5. 화면         src/lib/mapData.ts 가 아는 칸만 골라 담는다

**셋째가 가장 세다.** 값 검사는 조직 이름 같은 평범한 낱말을 못 잡는다. 키로 막으면 값이
무엇이든 새 칸이면 걸린다. `npm test` 앞에 `bake:check` 가 돈다.

## 배포

**자동으로 된다.** 레포의 `.github/workflows/map.yml` 이 하루 두 번(KST 14:30 · 02:30) 노션에서 굽고
반출 검사 · 시험 · 빌드를 거쳐 배포한다. 한 단계라도 실패하면 배포하지 않는다. Actions 탭에서
「지도 갱신」을 손으로 돌릴 수도 있다. 비밀값 열둘(노션 토큰 · Cloudflare 둘 · DB id 아홉)은
워크플로 머리 주석에 적었다.

손으로 배포할 때는 이렇게 한다.

```
npx wrangler login      # 한 번만
npm run deploy          # 시험 → 빌드 → out/ 을 Cloudflare 에 올린다
```

**굽지 않았으면 배포가 멈춘다.** 빈 파일로 물러서면 예시 데이터가 실제 사이트에 올라가므로
`predeploy` 가 구운 파일인지 먼저 본다.

코드가 도는 Worker 가 아니라 자산만 올리는 배포다. `out/` 밖의 것은 못 올라간다.

**검색 색인을 거부한다.** 세 겹이다 — `public/robots.txt`, 화면 `<head>` 의 robots meta
(`src/app/layout.tsx`), 모든 파일에 붙는 `X-Robots-Tag` (`public/_headers`). 공개로 돌릴 때
셋을 같이 푼다. `_headers` 에는 보안 헤더(CSP · Referrer-Policy · X-Frame-Options 등)도 있다.
CSP 의 `connect-src 'self'` 가 화면이 다른 곳을 부르지 못하게 막는다.

배포 전에 헤더가 붙는지 로컬에서 볼 수 있다 — `npm run build` 뒤
`npx wrangler dev --port 8788` 로 띄우면 Cloudflare 와 같은 규칙으로 헤더가 붙는다.
