다크웹의 포럼 · 랜섬웨어 그룹 · 텔레그램 채널 · 행위자를 유형별 섬으로 묶은 헥사 지도다.
칸이 넓을수록 사건과 활동이 많은 곳이다.

                팀 구글 드라이브. PDF 와 엑셀이 어긋나면 엑셀 수식을 따른다

## 여는 법

```
npm install
npm run dev          # http://localhost:3000
npm test             # 반출 검사 + 시험
npm run build        # out/ 에 정적 파일
```

**새 클론은 예시 데이터로 뜬다.** 구운 파일(`src/data/map.json`)이 저장소에 없어서,
`dev` · `build` · `test` 앞에 `tools/ensure_map.mjs` 가 빈 파일을 만든다. 실제 지도를 보려면
아래 「굽기」를 먼저 돌린다.

## 자료가 흐르는 길

    노션 (사람이 판정 · 검토 · DB 반영을 찍는다)
      └ tools/bake.py  ── 반출 검사 ──→  src/data/map.json  ──→  화면
                                          (저장소에 안 들어간다)

**구운 파일은 저장소에 넣지 않는다** (2026-09-25). 공개 지도가 내보내는 것과 같은 자료지만,
공개 저장소의 git 기록에 한 번 들어가면 못 지우고 검색 엔진에 색인된다. 루트 `.gitignore` 의
`data/` 규칙이 막는다.

**화면은 노션을 직접 부르지 않는다.** 구운 파일만 읽는다. 화면에서 노션을 부르면 반출 관문이
사라진다. 원천은 Supabase(`darkchoco-data` 의 `core` · `map`)로 옮길 예정이다 —
`tools/supa.py` · `tools/supa_schema.py` 가 1단계(칸 목록)까지 되어 있다.

### 굽기

```
NOTION_TOKEN_FILE=~/.config/darkchoco/NOTION_TOKEN_산출물.txt npm run bake
```

읽는 DB 는 `~/.config/darkchoco/map_sources.json` 이나 환경변수 `DC_MAP_<KEY>_DS` 로 받는다.
**DB id 를 저장소에 박지 않는다.** 값은 database id 가 아니라 data_source id 다.

    collect · verify                 수집 DB · 검증 DB
    forum · telegram · ransomware    게시처 DB 셋 — 이 줄들이 영토가 된다
    actor                            행위자 DB — 행위자 섬 영토가 된다
    relations                        관계선 DB (없어도 굽는다)
    incident                         유출 사고 DB — 공식 발표 사고 (없어도 굽는다)
    address                          주소 변경 이력 DB — 포럼 옛 · 새 주소를 맞추기 별칭으로 (없어도 굽는다)

**행위자 섬은 행위자 DB 줄에서 만들고, 사건과는 수집 DB 「게시자 핸들」로 잇는다** (2026-09-25
22시 최현서 — 행위자 정보를 받으려면 행위자 DB 를 읽어야 한다). 게시자 핸들은 맞추기 전용이라
밖에 안 낸다. 행위자 DB 에 없는 핸들의 사건은 행위자 영토를 안 만든다. 랜섬웨어 섬 사건의
핸들과, 랜섬 그룹 · 지도에 남은 영토 이름과 같은 핸들은 잇지 않는다. 9/25 낮에 잠시 게시자
핸들로 영토를 만들었다가(#47) 같은 날 밤 되돌렸다.

**행위자 정보 칸을 싣는다** (설계서 4.3.8, 2026-09-26 최현서). 역할 · 국가(선택지), 처음 본 날(날짜),
다루는 것 · 다른 이름(사람이 쓰는 글)이다. 사람이 쓰는 두 칸은 수집 DB · 유출 사고 DB 조직 이름과
겹치면 빼고, 값 훑기를 통과해야 하며, 다른 이름은 핸들 모양(글자 · 숫자 · `_` · `-`, 2~32자)만
싣는다. 9/23 검토가 별칭을 막은 까닭(메모 · 자리표시가 섞임)을 모양 검사로 거른다.

**공식 발표 사고(유출 사고 DB)를 사건으로 넣는다** (설계서 2.4 · 2.5 · 3.2, 2026-09-26 최현서 —
읽어도 된다. 조직명은 지도 어디에도 안 낸다). 공표 시점이 게시 시각, 보도된 유출 위치가 영토다.
위치는 게시처 이름과 그대로 맞거나 랜섬 그룹 유출 사이트(DLS)라고 적혔을 때만 맞춘다. 판정은
확인됨, 규모는 유출 규모 칸의 숫자다. 수집 DB 와 같은 사고는 정본 작업판이 짝지은 사건 번호 표
(`SAME_AS_COLLECT`)와 조직 이름 전체 대조로 뺀다. 조직명 · 보도된 유출 위치 · 보도된 행위자는 맞추기
전용이고 출처 링크 · 메모는 안 읽는다. 사고 시점 · 유출 항목 · 외부 확인 · 출처 종류(선택지)만
싣는다.

**공식 발표는 「외부 확인」이 조직 공식 발표 · 규제기관 확정 · 언론 보도인 사고만이다** (2026-09-28
최현서). 연구자 발견 · 게시글만인 사고와 외부 확인이 빈 사고는 싣지 않는다 — 조직이 아직 인정하지
않은 사고가 「공식 발표 · 확인됨(신뢰 1.0)」으로 나가던 것을 막는다. 가르는 것은 외부 확인 칸이지
출처 칸이 아니다. 언론이 다크웹 게시글을 보도했을 뿐이면 출처는 언론 보도여도 외부 확인은 게시글만이다.
**설계서 그대로다 — 코드 필터는 안전장치다.** 설계서는 「공식 발표 = 유출 사고 DB 1행」이고 공식 확인
사고만 DB 에 있다고 가정한다. 2026-09-28 에 최현서가 외부 확인이 게시글만 · 연구자 발견인 122줄의 「DB
반영」을 꺼서 DB 를 그 가정에 맞췄다. 이 필터는 그런 줄이 다시 켜져 들어와도 공식 발표로 나가지 않게
막는 안전장치로 남는다. 반출 검사(`check`)도 외부 확인이 이 세 값이 아닌 공식 발표 사건을 막는다.
2026-09-28 굽기에서 316줄 중 5건이 지도에 올랐다 (이 규칙 전에는 8건, 정본 9/22 는 9건).

**다크웹 게시와 같은 사고로 특정된 공식 발표 사고는 그 게시에 「공식 발표 여부」로 붙인다** (설계서 사건
칸 「공식 발표 여부」, 2026-09-28 최현서). 특정된 짝은 정본 작업판이 짝지은 사건 번호 표(`SAME_AS_COLLECT`,
17쌍)와 유출 사고 DB 메모에 사람이 적은 INC-241 ↔ LEAK-183 뿐이다. 표는 「사고 → 게시 목록」 꼴이다.
이름 대조로만 같다고 본 사고와 묶음 사고(INC-242 · 243 — 기간 · 게시자로 추론한 소속)는 잇지 않는다.
**특정되지 않은 이상 추론으로 잇지 않는다** — 묶음 사고는 지금처럼 따로 된 공식 발표 사건으로 센다.

- 붙는 조건은 사고 줄의 「DB 반영」이 켜져 있고 외부 확인이 공식 3값인 것뿐이다. 위치 · 공표 시점은 안
  따지고 게시의 영토를 쓴다. 게시 쪽도 지도에 오른 게시여야 한다. 붙은 사고는 따로 된 사건으로 만들지
  않는다. 「같은 사건」을 따라 재게시에 붙이지 않는다
- 게시의 판정 · 점수는 안 바꾼다. 공식 발표와 어긋나는 짝(게시 판정이 신뢰성 낮음 · 허위)은 굽기 로그에
  번호만 남긴다
- 싣는 칸은 `incident` 하나이고 속 키는 사고 번호 · 외부 확인 · 공표일 · 게시와 공표 사이 일수다. 조직명은
  없다. 일수는 게시일 − 공표일이다. 시각이 붙은 값만 한국 날짜로 옮기고, 게시일을 대신 넣은 사건은 일수를 안 둔다
- 반출 검사가 속 키 · `INC-숫자` 모양 · 외부 확인 · 날짜 모양을 보고, 같은 사고가 게시마다 다르게 나가거나
  따로 된 사건으로도 있으면 멈춘다
- 화면: 사건 줄과 보고서 팝업에 「공식 발표」 칩과 외부 확인 값, 팝업 표에 공식 발표 사고 · 공표 시점 · 게시와
  공표 사이(「발표 n일 전 게시」 · 「발표 n일 뒤 게시」, 하루 안쪽은 「같은 날 무렵」). 새 칩 이름은 안 만든다
- [개요] 「공식 발표 사고」 절은 게시에 붙은 사고도 사고 번호당 한 번 센다. 기준일에는 공표일로 넣고,
  공표일이 빈 사고는 「공표 기록 없음」으로 맨 뒤에 둔다. 붙은 사고는 규모를 안 적는다(사고 규모를 안
  싣는다). 허위 · 반출 제외 게시에 붙은 사고는 안 센다

**설계서와 다른 곳:** 설계서는 사건 칸에 「공식 발표 여부」를 두었지만 채우는 규칙은 적지 않았다. 특정된 짝만
쓰는 규칙은 2026-09-28 최현서가 정한 것이다. 2026-09-28 굽기에서 LEAK-10(INC-200) · LEAK-13(INC-199) ·
LEAK-170 · 183(INC-241) 넷에 붙었다. INC-200 은 위치가 지도 영토와 안 맞아 따로는 안 보이던 사고다.

**사건마다 위험도 · 연결된 사건 · 사기 의심 표시를 싣는다.** 위험도(설계서 3.10)는 검증 DB
「즉시 악용 가능성」과 유출 항목으로 굽기가 매기고 재료는 안 싣는다 (`score.ts` `riskLevel` 과 같은
규칙). 연결된 사건은 수집 DB 「같은 사건」 두 칸을 사건 번호로 바꿔, 지도에 오른 사건끼리만 잇는다.
「사기 의심」은 칩 없이 필터용 표시다 (2.3). 「랜섬웨어 유출」은 파일 공개가 확인돼야 데이터 게시,
아니면 피해 주장이다 — 정본과 같다 (9/25 판은 반대였다).

**텔레그램 소스 사건은 그 글을 올린 채널의 사건이다** (설계서 3.3 「텔레그램 재유포 사건의 채널 정하는
방법」). 원래 게시처(포럼 · 랜섬 사이트)가 따로 있어도 포럼 · 랜섬 영토로 옮기지 않는다 — 텔레그램 섬은
재유포(확산)를 잰다 (2026-09-28 최현서). 채널은 **게시 플랫폼의 t.me → 원문 URL 의 t.me → 채널 이름과
같은 게시자 핸들** 순서로 찾고, 못 찾으면 확인필요로 빠진다. 원문 URL 은 9/28 까지 안 읽는 칸이었다.
지금은 `TME_ONLY_COLS` 라 `col_tme()` 로만 읽는다. 돌려받는 값은 t.me 뒤 채널 이름뿐이고, 그 이름도
텔레그램 DB 줄을 찾는 데만 쓴다. URL 은 어디에도 안 싣고, t.me 가 아닌 주소(포럼 글 주소 · 피해 조직
도메인)는 읽자마자 버린다.

**3.12 운영 규칙 가운데 셋을 굽기가 한다.** 노션 줄에 없던 칸을 DB 별로 로그에 남기고(칸이 지워지거나
이름이 바뀌어도 멈추지 않는다), 영토를 정할 수 없는 사건 번호를 「확인필요」로 찍고, 사람이 손으로
고친 사건 값을 `tools/overrides.json` 에서 먼저 쓴다(파일이 없으면 아무 일도 안 한다. 조직명을 적지
않는다 — 공개 레포다).

## 계산 규칙 (정본)

    사건 점수     신뢰 × 규모                         허위는 0
    사건 지수     round(100 × ln(1+Σ사건 점수) ÷ ln(1+섬 최댓값))
    활동도        명부 규모 원자료를 같은 식으로 누른 값. 포럼은 회원 · 게시물 · 스레드
                 지수의 평균(빈 지수는 뺀다). 행위자는 사건 수
    영토 점수     (사건 지수 + 기본점 20) × (0.5 + 활동도 ÷ 200)
    섬 몫         round(800 × S(I)^0.6 ÷ Σ) — 합이 어긋나면 가장 큰 섬에 끝전
    칸 수         섬 안에서 최대 나머지 방식. 0칸이면 1칸

`src/lib/score.ts` 가 전부 한다. 반올림은 엑셀 ROUND 와 같다 (0.5 는 0 에서 먼 쪽).

- **행위자 섬은 같은 사건을 한 번 더 센다.** 지도 사건 수는 한 번씩이다
- **날짜를 대신 넣은 사건**(게시 시각이 없어 관측 시각 · 수집일을 넣은 것)은 점수와 칸에는
  들고, 최근 30일 · 7일 창 · 상태 · 급상승에서는 빠진다
- 영토는 첫 사건이 있는 분기부터 나온다. 사건이 없는 명부 영토는 이번 분기에만 나온다
- **랜섬웨어 활동도 원자료는 약 여섯 달 피해 건수다.** 게시처 DB 규모가 「피해 월평균 M건 (최근 D일)」
  꼴이면 M × D ÷ 30 으로 돌려 옛 「피해 기업 N」 과 같은 단위로 읽는다. 두 꼴이 한 섬에 섞여도
  쉬는 그룹이 활발한 그룹보다 크게 그려지지 않는다 (2026-09-25)

### 관계선

세 화면이 같은 관계를 본다. 지도 위 관계선(설계서 4.2.3), 패널 [연결] 탭(4.3.1 · 4.3.2 · 4.3.8),
관계 탭(4.3.3 · 4.3.6)이다. **건수는 `src/lib/relations.ts` 의 `relationsAt` 하나에서 나온다**
— 설계서 3.9 가 세 화면의 건수가 같아야 한다고 정했다.

- 건수는 기준일에 지도에 든 근거 사건 수다. 근거가 처음부터 없는 관계(명부 「연결된 곳」
  칸에서 만든 것)는 1건으로 센다
- **활동 관계(행위자 → 영토)는 사건에서 만든다.** 노션 관계선 DB 의 활동 줄은 사건에서
  나오는 쌍의 일부라, DB 줄은 번호와 신뢰도만 쓰고 근거는 그 행위자가 그 영토에 올린 사건
  전부로 둔다
- 근거 목록은 날짜 · 판정 · 규모 · 올라온 곳만 보인다. 사건 제목에 피해 조직 이름이 든다
- **근거 사건이 없는 관계선은 명부 「연결된 곳」 원문을 보인다** (설계서 4.3.6, 2026-09-25 최현서).
  두 영토의 그 칸에서 상대 이름이 든 항목만 골라 `note` 로 싣는다. 가해 쪽 주소는 들어도 된다.
  수집 DB 「대상 조직」 이름과 겹치는 항목과 @ · 긴 숫자열이 든 항목은 굽기가 뺀다

### 화면 조작 — 설계서와 다른 곳 (G-10)

2026-09-28 최현서가 배포된 지도를 보고 짚은 고칠 점(열 가지)과 그와 비슷한 문제를 고치며 설계서와
달라진 곳이다. 모두 최현서가 정한 것이다.

- **상세 패널 펼침은 화면 전체에 하나다** (최현서 2번). 설계서 4.2.4 는 「첫 진입 접힘 · 섬/영토 클릭
  자동 펼침 · 선택 해제 시 다시 접힘」이고, 전 코드는 탭을 옮길 때마다 지도 · 관계 탭만 펼쳐서 화면 탭
  단추 자리가 탭마다 옮겨 다녔다. 이제는 이렇게 한다
  - 펼침은 사람이 핸들로 바꾼 값이 기준이고 탭을 옮겨도 그대로다
  - 섬 · 영토 · 관계를 고르면 펼치되, 선택을 풀어도 접지 않는다
  - 엔티티 탭 섬 필터처럼 패널을 건드릴 까닭이 없는 조작은 패널을 안 펼친다(표만 거른다)
  - 첫 화면은 펼침이다
  - 핸들 화살표는 누르면 갈 쪽이다 — 펼쳐져 있으면 ›, 접혀 있으면 ‹ (설계서 · 피그마는 둘 다 ‹)
- 검색 전체 결과 화면에서도 화면 탭을 둔다. 「검색 결과 닫기 ×」는 결과 목록 머리로 옮겼다
- **사건 줄은 한 번 누르면 보고서 팝업이 열린다** (최현서 9번). 설계서 4.3.2 L587 · 4.3.3 L607 ·
  4.3.4 · 4.3.5 L745 · 4.3.6 L786 은 「클릭: 강조 / 더블클릭: 보고서 팝업」이다. 패널 [사건] · 엔티티 탭
  「최근 주요 이벤트」 · 관계 패널 「근거 사건」이 한 부품(`EventRow`)을 써서 셋이 같이 바뀐다. 누르면 그
  줄을 강조하고 팝업을 연다 — 팝업을 닫아도 강조가 남아 지도 · 그래프에 그 사건의 관계선이 보인다.
  키보드는 Enter 가 팝업, Space 가 강조 켜고 끄기다. 「더블클릭 시 상세」 같은 안내 문구도 고쳤다
- [연결] 탭 줄은 설계서대로 한 번 = 미리보기(지도에 그 관계선), 두 번 = 관계 탭이다. 다만 「관계 보기 ›」
  단추가 마우스를 올린 줄뿐 아니라 **고른 줄에서도 보여서** 한 번 클릭으로도 관계 탭에 갈 수 있다
  (설계서 4.3.3 L604 는 마우스를 올릴 때만)
- 지도 마우스 올림은 섬 색에 흰색을 섞은 밝은 채움과 밝은 테두리이고, 고른 영토는 밝은 윤곽선이다
  (최현서 6번). 설계서 · 피그마 시트 `DW/Hex v2` 는 한 단계 진한 채움이고 고른 영토 윗면이 그 색이었다

- **타임라인 지도(Historical Map · 시점 비교 A/B)는 지도 탭과 같은 캔버스다** (최현서 3번 「블록의 기능은
  2D 지도와 같다」). 줌 · 끌기 · 툴팁 · 누르면 고르기가 되고, A · B 는 줌 · 이동을 같이 쓴다. 설계서
  4.3.7 은 이 지도를 보기 전용으로 그렸다
- **관계도에도 줌이 있다** (최현서 5번). 설계서 4.3.6 은 줌을 정하지 않았다. 지도와 같은 50~200%, 25%
  단위이고 끌어 옮길 수 있다. 라벨(「종류 건수」 알약)은 배율에 따라 단다 — 100% 미만은 1단계 건수 상위
  넷, 100% 는 1단계 전부, 125% 이상은 2단계 바깥 선까지. 선은 늘 그린다. 라벨끼리 · 노드 이름과 겹치면
  뺀다(강조 · 고른 선은 늘 단다). 알약은 확대할수록 판 단위로 작아져 확대하면 더 많이 들어간다. 범례는
  접을 수 있고 펼쳐져 있으면 그래프를 그만큼 오른쪽으로 민다. 근거 팝오버에 닫기 × 가 있다
- 지도 탭도 관계선 라벨을 배율에 따라 단다 — 100% 미만 넷, 150% 미만 여덟, 그 이상 전부(겹치면 뺀다).
  마우스를 올린 영토의 선은 늘 단다. 휠은 모아서 한 단계씩 옮긴다(`lib/zoom.ts`)

- **시점을 옮기면 섬이 옮겨 간다** (최현서 7번 「지구본에서 대륙이 이동하는 것처럼」). 설계서 4.2.5 · 4.3.7 은
  바로 바뀌는 화면이다. 칸 배치는 분기마다 새로 계산돼 칸째 이을 수 없어, 섬 단위로 앞 분기 자리 · 크기에서
  새 자리 · 크기로 `--dur-slow`(480ms) 동안 옮겨 간다(FLIP, `lib/motion.ts`). 새로 생긴 섬은 번져 나오고
  관계선은 다시 번져 나온다. 지도 탭 슬라이더 · 재생 · 「기준일로」, 타임라인 연도 칩 · 스냅샷 카드 · ◀ ▶▶ ·
  슬라이더가 모두 지도 그림 부품(`HexMap`) 하나를 거쳐 같은 움직임이다. 움직임 줄이기를 켜면 안 움직인다
- 스냅샷 바에도 재생 속도(1× · 2× · 4×)가 있고 타임라인과 같은 값이다

- **시점 비교는 A · B 를 따로 고른다** (최현서 8번). 설계서 4.3.7 L812 는 「연도 칩에서 첫 번째 클릭이 A,
  두 번째가 B」라 누를 때마다 A · B 를 번갈아 채웠다. 이제는 「A 고르기 · B 고르기」 단추로 연도 칩이 채울
  쪽을 정한다. A 는 늘 B 보다 앞선 시점이다 — 같은 시점이거나 순서를 거꾸로 만드는 칩은 꺼져 있고, 마우스를
  올리면 붉게 바뀌며 어느 쪽을 먼저 옮길지 알린다
- 「신규」는 앞 시점에 사건이 없었는데 뒤 시점에 사건이 있는 영토다. Historical Map 「신규」 칩(직전 분기
  대비)과 시점 비교 「신규 영토」(A 대비)가 같은 기준이다. 설계서 L806 · L814 는 이름만 있고 기준은 없다
- 관계 탭에 갔다 「돌아가기」로 오면 시점 비교와 엔티티 표 정렬이 그대로다

- **관계 탭에도 스냅샷 바가 있다** (최현서 10번). 피그마 ⑦-8 에는 없어 기준일을 「기준일 옮기기」로만
  바꿀 수 있었다. 설계서 4.2.5 는 스냅샷 바를 탭마다 정하지 않았다. 시점을 옮기면 관계도가 그 기준일까지의
  관계로 다시 그려진다
- **엔티티 탭 「최근 주요 이벤트」는 섬 필터 바로 아래다** (최현서 10번). 설계서 4.3.5 · 피그마 ⑦-7 은 표
  아래라 표가 길면 굴려야 보였다. 엔티티 탭 본문은 제 칸 안에서만 굴러서 목록이 길어도 스냅샷 바는 늘 보인다

- 키보드로도 고른다. 지도의 영토 · 섬 이름표, 관계도의 선 · 이웃 노드, 엔티티 표 줄은 Tab 으로 옮겨
  Enter · Space 로 고른다. 설계서는 키보드 조작을 정하지 않았다. 화면의 분기는 모두 「2025 Q3」 꼴이다

눌리는 것의 마우스 올림은 공통 규칙 넷(`globals.css` 의 `hover-edge` · `hover-row` · `hover-seg` ·
`hover-accent`)에서 모양에 맞는 하나를 쓴다. 전환 시간은 `tokens.css` 의 `--dur-fast` · `--dur-base` ·
`--dur-slow` 이고, 움직임 줄이기를 켠 사람에게는 0 이다.

## 반출 경계

**피해 조직 이름은 지도에 내지 않는다** (2026-09-23 최현서 결정). 가해 쪽 — 포럼 · 랜섬웨어
그룹 · 텔레그램 채널 · 행위자 DB 에 등록된 행위자 — 는 영토 이름으로 낸다.

**이 결정은 공개 지도(`apps/map`)에만 적용된다.** 비밀번호 뒤 대시보드(`apps/dash`)는 범위
밖이다. 대시보드는 팀 안에서 검토하는 화면이라 사건 제목과 대상 조직을 보인다.

    1. 줄 관문      「DB 반영」이 꺼졌거나 「검토 여부」가 미검토 · 사건 X 면 뺀다
    2. 읽는 칸      ALLOWED_COLS 밖의 칸을 읽으면 멈춘다. 자료 제목 · 다크웹 주소 ·
                   출처 링크는 DENY_COLS. 대상 조직 · 게시자 핸들 · 조직명 · 보도된 유출 위치 ·
                   보도된 행위자는 대조 전용(MATCH_ONLY_COLS). 원문 URL 은 t.me 채널 이름만
                   뽑는다(TME_ONLY_COLS)
    3. 나가는 키    TERRITORY_KEYS · EV_KEYS · RELATION_KEYS 밖의 키가 있으면 멈춘다
    4. 값 훑기      도메인 · @ · 11자리 넘는 숫자열을 찾는다. 관계선 원문(note)만
                   도메인을 허용한다
    5. 화면         src/lib/mapData.ts 가 아는 칸만 골라 담는다

**셋째가 가장 세다.** 값 검사는 조직 이름 같은 평범한 낱말을 못 잡는다. 키로 막으면 값이
무엇이든 새 칸이면 걸린다. `npm test` 앞에 `bake:check` 가 돈다.

## 배포

**자동으로 된다.** 레포의 `.github/workflows/map.yml` 이 하루 두 번(KST 14:30 · 02:30) 노션에서 굽고
반출 검사 · 시험 · 빌드를 거쳐 배포한다. 한 단계라도 실패하면 배포하지 않는다. Actions 탭에서
「지도 갱신」을 손으로 돌릴 수도 있다. 비밀값 열둘(노션 토큰 · Cloudflare 둘 · DB id 아홉)은
워크플로 머리 주석에 적었다.

손으로 배포할 때는 이렇게 한다.

```
npx wrangler login      # 한 번만
npm run deploy          # 시험 → 빌드 → out/ 을 Cloudflare 에 올린다
```

**굽지 않았으면 배포가 멈춘다.** 빈 파일로 물러서면 예시 데이터가 실제 사이트에 올라가므로
`predeploy` 가 구운 파일인지 먼저 본다.

코드가 도는 Worker 가 아니라 자산만 올리는 배포다. `out/` 밖의 것은 못 올라간다.

**검색 색인을 거부한다.** 세 겹이다 — `public/robots.txt`, 화면 `<head>` 의 robots meta
(`src/app/layout.tsx`), 모든 파일에 붙는 `X-Robots-Tag` (`public/_headers`). 공개로 돌릴 때
셋을 같이 푼다. `_headers` 에는 보안 헤더(CSP · Referrer-Policy · X-Frame-Options 등)도 있다.
CSP 의 `connect-src 'self'` 가 화면이 다른 곳을 부르지 못하게 막는다.

배포 전에 헤더가 붙는지 로컬에서 볼 수 있다 — `npm run build` 뒤
`npx wrangler dev --port 8788` 로 띄우면 Cloudflare 와 같은 규칙으로 헤더가 붙는다.
