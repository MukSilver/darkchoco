# 이 저장소에서 코드를 쓸 때 지킬 것

다크초코 — LLM 다크웹 RAG DB. 방어적 보안 연구·교육 목적.
정본은 **시스템 명세서 DC-RAGDB-SYS-001 판 1.6**(2026-09-23)이다. **명세서, 계획안, 로드맵은 이 저장소에 넣지 않았다**(2026-09-29, 공개 저장소라서). 담당자(김무근)에게 있고 노션 「LLM RAG DB」 설계서 페이지에 설계서가 있다. 화면을 만들 때 보는 시각 기준은 `DESIGN.md`에 따로 있다.

## 첫째 규칙 — 명세서에 없는 기능은 만들지 않는다

명세서 1.1이 규정한다. 만들고 싶은 것이 생기면 **코드보다 명세서를 먼저 고친다.**
고치지 않고 넣은 기능은 되돌린다.

## 절대 하지 않는 것

- **다크웹에 직접 접속하지 않는다** (CR-02). 입력구는 Supabase rag 하나다(정제 배치가 노션에서 만든다).
- **모델을 학습시키지 않는다** (CR-03). 파인튜닝은 조건부가 아니라 금지다.
- **노션에 쓰지 않는다** (CR-09). 판 1.6 부터는 노션을 읽지도 않는다. 노션 토큰을 두지 않는다. 노션을 읽고 표준 문서로 바꾸는 코드는 darkchoco-data 의 `src/rag.mjs` 에 있다.
- **노션 줄을 지우지 않는다** (CR-06).
- 키·토큰을 코드나 지시문에 적지 않는다 (SR-10 · SR-11). `.env`에서만 읽는다.
- 임시 터널을 쓰지 않는다 (CR-07). SSE가 끊긴다.

## 나가는 것을 다룰 때

**기본값은 「안 내보냄」이다.** 헷갈리면 안 내보낸다.

- 반출 판정은 2단계다 — 줄 판정(「DB 반영」 하나. 판 1.5 AD-20) → 칸 판정(반출하는 칸 목록). DR-07 · AD-07
- 읽는 칸 목록과 반출하는 칸 목록은 **다른 목록**이다. 하나를 통과했다고 다른 하나를 통과한 것이 아니다.
- 바깥 사업자(Claude · 재순위)에게 보내는 것은 **질문 원문과 반출 통과 조각 본문뿐**이다. SR-19
  넓힌 낱말·넓힌 질문·지시문·키는 보내지 않는다.
- `terms.json` · `excluded_rows.json` · `recheck_queue`는 **배치만 읽는다.** 웹 서버가 읽으면 안 된다. SR-01

## 배치와 웹 서버는 다른 프로세스다 — AD-02

같은 프로세스에 넣으면 질의가 21.4ms에서 3,733.8ms가 된다(실측). 원인은 형태소 분석의 CPU 독점이다.
웹 서버 워커는 측정 전까지 **하나**로 고정한다 — 워커마다 색인이 따로 상주한다(2.4).

## 색인을 갈아 끼울 때

제자리에서 덮어쓰지 않는다. **새 판 폴더에 다 만든 뒤 `current.txt` 한 줄만 바꾼다.**
질의는 시작할 때 `current.txt`를 한 번 읽어 끝까지 그 판을 쓴다. F-06 처리 5 · F-12 처리 1

## 값을 지어내지 않는다

명세서에 미결(OI-nn)로 적힌 값은 **아직 정해지지 않은 것**이다.
코드에 상수로 박지 말고 설정에서 읽되, 기본값을 정했으면 그 사실을 커밋 메시지에 남긴다.
지금 열려 있는 것 가운데 코드에 바로 걸리는 것 — OI-02(M·K) · OI-03(최소 길이) · OI-14(무게 w) ·
OI-15(상한) · OI-21(대기 상한) · OI-30(답 길이와 질문 길이).
사용 한도(IP 해시 동시 1, 1분 5, 1시간 30, 하루 3달러)는 OI-09를 닫으며 정한 초기값이다. 역시 설정에서 읽는다.

## 명세서에 올릴 것이 생기면

만들다 보면 명세서에 없는 세부를 정하게 된다. 그때마다 문서를 고치면 PDF를 다시 만들고
노션에 올리는 값이 든다. 담당자가 가진 「명세서에 반영할 것」 목록에 쌓아 두고 **단계 관문에서 한 번에 반영한다.**

다만 **기능을 새로 만드는 것은 다르다.** 그건 명세서를 먼저 고친다(위 첫째 규칙).
세부를 정하는 것과 없던 것을 만드는 것을 가른다.

- 세부를 정함 — document_id를 어떤 꼴로 만들지, 어느 칸을 summary로 쓸지 → 쌓아 둔다
- 없던 것을 만듦 — 화면을 하나 더, API를 하나 더, 저장물을 하나 더 → 명세서를 먼저 고친다

## 배치 순서 (판 1.6)

`.venv\Scripts\python scriptsefresh.py` 하나가 아래 셋을 잇는다. 새 판이 없으면 아무것도 하지 않는다.

1. `fetch_docs.py` — Supabase rag.versions 의 마지막 판이 `data/source_version.txt` 와 다르면 rag.documents · rag.private 을 받아 `data/standard/` 에 쓴다. 판에서 빠진 문서는 파일을 지운다 (F-01)
2. `chunk.py` — 조각과 목록 (F-05)
3. `build_index.py` — 금지어 검사(`masking.py`) 뒤 새 판 폴더에 색인 (F-06)

표준 문서의 모양을 바꾸려면 이 저장소가 아니라 darkchoco-data 의 `src/rag.mjs` 를 고친다. 바꾸면 이 저장소의 chunk.py 가 그대로 읽는지 확인한다.
