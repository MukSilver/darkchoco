# 이 저장소에서 코드를 쓸 때 지킬 것

다크초코 — LLM 다크웹 RAG DB. 방어적 보안 연구·교육 목적.
정본은 **설계서 DC-RAGDB-DES-001**(노션 「LLM 다크웹 RAG DB 구축 / 설계서」)이다. 문서는 설계서 하나만 둔다. 시스템 명세서는 없앴다(2026-09-30).
RAG DB 는 묻고 답하는 곳이다. 목록, 상세, 내려받기 화면과 관리 화면은 만들지 않는다. 운영은 터미널 스크립트로 한다. 화면 디자인은 새로 짠다.

코드 주석에 나오는 F-12, SR-19, TC-06, OI-03 같은 번호는 옛 명세서의 항목 번호다. 뜻은 설계서 「코드 주석의 번호」에 있다. 새로 쓰는 주석에는 설계서의 절 번호를 쓴다.

## 첫째 규칙 — 설계서에 없는 기능은 만들지 않는다

만들고 싶은 것이 생기면 **코드보다 설계서를 먼저 고친다.**
고치지 않고 넣은 기능은 되돌린다.

세부를 정하는 것과 없던 것을 만드는 것을 가른다.

- 세부를 정함 — 값 하나, 파일 이름, 칸 순서 → 코드에 넣고 설계서 다음 판에 같이 올린다
- 없던 것을 만듦 — 화면을 하나 더, API를 하나 더, 저장물을 하나 더 → 설계서를 먼저 고친다

## 도구를 새로 들이지 않는다 — CR-01

쓰는 것은 설계서 「개발 스택」에 적힌 것뿐이다.

| 자리 | 쓰는 것 |
|---|---|
| 웹 서버 | FastAPI · Python |
| 화면 | React + Vite + TS · Tailwind |
| 검색 | bm25s · kiwipiepy · cohere SDK. 벡터 검색은 쓰지 않는다 |
| 답변 | anthropic SDK · Claude Sonnet |
| 저장 | 운영 기록은 Supabase rag 스키마(`app/store.py`). 색인과 판은 파일. SQLite 는 쓰지 않는다(2026-09-30) |
| 입력 | Supabase rag 스키마 (httpx로 받음). 정제 배치 darkchoco-data 가 노션에서 만든다 |
| 공개 | Cloudflare 정식 터널 (cloudflared 서비스). 터널은 API 주소 하나만 |
| 화면 배포 | Cloudflare 정적 호스팅 (rag.도메인), API는 rag-api.도메인 |
| 서버 실행 | 클라우드 리눅스 서버 하나, systemd 서비스. 옮기기 전까지는 운영 PC |
| 배치 실행 | 같은 서버, cron 주 1회와 손으로. 옮기기 전까지는 윈도우 작업 스케줄러 |
| 사람 확인 | Cloudflare Turnstile, 서버에서 토큰 검증 |
| 화면 올리기 | wrangler (Workers 정적 자산) |
| 감시 | Cloudflare Workers 예약 실행 5분마다, 디스코드 웹훅 |

라이브러리를 하나 더 넣어야 하면 **설계서의 그 표를 먼저 고친다.** 도커는 쓰지 않는다.

## 절대 하지 않는 것

- **다크웹에 직접 접속하지 않는다** (CR-02). 입력구는 Supabase rag 하나다(정제 배치가 노션에서 만든다).
- **모델을 학습시키지 않는다** (CR-03). 파인튜닝은 조건부가 아니라 금지다.
- **노션에 닿지 않는다** (CR-09). 읽지도 쓰지도 않는다. 노션 토큰을 두지 않는다. 노션을 읽고 표준 문서로 바꾸는 코드는 darkchoco-data 의 `src/rag.mjs` 에 있다.
- **노션 줄을 지우지 않는다** (CR-06).
- 키·토큰을 코드나 지시문에 적지 않는다. `.env`에서만 읽는다.
- 임시 터널을 쓰지 않는다 (CR-07). SSE가 끊긴다.

## 나가는 것을 다룰 때

**기본값은 「안 내보냄」이다.** 헷갈리면 안 내보낸다.

- 반출 판정은 2단계다 — 줄 판정(「DB 반영」 하나, 정제 배치가 지킨다) → 칸 판정(`export_columns.json`).
- 바깥 사업자(Claude · 재순위)에게 질의 때 보내는 것은 **가린 질문과 가린 조각 본문뿐**이다.
  넓힌 낱말·넓힌 질문·지시문·키는 보내지 않는다.
- 예외는 조직 표기 찾기(`find_names.py`) 하나다. 가릴 표기를 찾으려면 아직 다 가리지 않은 글을 모델이 읽어야 한다. 설계서 「가리기」에 적혀 있다.
- `terms.json` · `guard.json` · `names.json` · `excluded_rows.json` 은 밖으로 내보내지 않는다.

## 조직 이름과 주소는 내보내지 않는다

2026-09-29 팀 결정, 2026-09-30 김무근. 답변, 스냅샷, 질의 때 바깥 사업자에게 가는 조각 어디에도 피해 조직 이름과 URL 이 나오면 안 된다.

- 나가는 글은 반드시 `app/guard.py` 를 거친다. 새로 내보내는 자리를 만들면 거기에도 건다. 저장해 둔 답(사전 답변, 재사용 답변)을 내보낼 때도 건다.
- 조직 표기 목록(`data/names.json`)과 판 폴더의 `guard.json` 은 피해 조직 이름 그 자체다. 저장소에 넣지 않고 화면, API, 스냅샷, 로그 어디에도 내보내지 않는다.
- 로그와 알림에는 걸린 값을 찍지 않는다. 어느 문서의 어느 자리에서 무엇이 걸렸는지만 찍는다.
- 시험 자료는 지어낸 이름만 쓴다. 실제 조사 기록과 실제 조직 이름을 시험이나 예시에 넣지 않는다.

## 판은 폴더 하나로 닫혀 있다

제자리에서 덮어쓰지 않는다. **새 판 폴더에 다 만든 뒤 `current.txt` 한 줄만 바꾼다.**
질의는 시작할 때 `current.txt`를 한 번 읽어 끝까지 그 판을 쓴다.

질의가 읽는 것(색인, `ids.json`, 조각 본문 `chunks.json`, 넓히기 사전 `terms.json`, 지킴이 목록 `guard.json`)은 전부 판 폴더에 있다.
`data/staging/` 은 배치가 조각을 만들어 두는 작업 자리다. **질의가 거기서 본문을 읽게 만들지 않는다.** 배치가 중간에 멈추면 색인과 본문이 다른 판이 된다.

## 배치와 웹 서버는 다른 프로세스다 — AD-02

같은 프로세스에 넣으면 질의가 21.4ms에서 3,733.8ms가 된다(실측). 원인은 형태소 분석의 CPU 독점이다.
웹 서버 워커는 **하나**로 고정한다 — 워커마다 색인이 따로 상주한다.

## 값과 자리는 설정에서 읽는다

값은 `.env` 에서 읽는다(`app/config.py`). 코드에 상수로 박지 않는다. 기본값과 까닭은 `.env.example` 에 있다.
자리(`data/` 아래 경로)도 `app/config.py` 의 것을 쓴다. 스크립트가 따로 경로를 만들지 않는다.
「첫 값」 이라고 적힌 것은 평가 질문으로 재기 전의 출발점이다. 설계서 「보류 및 확정 필요」에 모아 두었다.
사용 한도는 하루 3달러(하루 차단기)다. 사람별 제한은 쓰지 않는다.

## 윈도우 콘솔

이 PC 콘솔은 cp949라 한글 밖 문자(— · ① 같은 것)를 찍으면 UnicodeEncodeError로 죽는다.
사람이 보는 출력이 있는 스크립트는 맨 위에 이것을 넣는다.

    if hasattr(sys.stdout, "reconfigure"):
        sys.stdout.reconfigure(encoding="utf-8")
        sys.stderr.reconfigure(encoding="utf-8")

파일을 읽고 쓸 때도 `encoding="utf-8"` 을 반드시 준다. 기본값이 cp949다.

## 배치 순서

`.venv\Scripts\python scripts\refresh.py` 하나가 아래를 잇는다. 새 판이 없으면 아무것도 하지 않는다. 하나라도 실패하면 거기서 멈추고 지금 판을 그대로 쓴다. 멈춘 배치는 다음 회차에 받아 둔 자료로 이어서 만든다(`data/pending_build.txt`).

1. `fetch_docs.py` — Supabase rag.versions 의 마지막 판이 `data/source_version.txt` 와 다르면 rag.documents · rag.private 을 받아 `data/standard/` 에 쓴다. 판에서 빠진 문서는 파일을 지운다
2. `find_names.py` — 바뀐 문서에서 피해 조직 표기를 모델로 찾아 Supabase `rag.found_names` 에 쌓고 `data/names.json` 에 사본을 쓴다. 모델이 놓친 표기는 `add_names.py` 로 손으로 더한다
3. `chunk.py` — 가리기(`app/guard.py`, `app/pii.py`)와 조각 분할. 이름 찾기를 안 거친 문서는 뺀다. 개인정보 꼴은 그 자리만 가린다
4. `build_index.py --hold` — 금지어 검사(`masking.py`) 뒤 새 판 폴더에 색인, 조각 본문(`chunks.json`), 넓히기 사전(`terms.json`), 지킴이 목록(`guard.json`)
5. `snapshot.py` — 스냅샷 굽기와 반출 관문
6. 갈아 끼우기 — `current.txt` 한 줄, 근거 문서가 바뀐 재사용 답변 지움, 반출 기록. 재사용 답변은 답에 쓴 문서가 그대로면 판이 바뀌어도 남는다. 지시문이나 모델이 바뀌면 쓰지 않고 새로 답한다(`answer.answer_tag()`)
7. `recheck.py` — 재조사 추출
8. Supabase `rag.batch_log` 에 한 줄

표준 문서의 모양을 바꾸려면 이 저장소가 아니라 darkchoco-data 의 `src/rag.mjs` 를 고친다. 바꾸면 이 저장소의 chunk.py 가 그대로 읽는지 확인한다.
